# Хостинг-скрипты (Beget, `/0s3/blogger-cron/`)

Это **рабочие копии** скриптов, которые реально публикуют посты и собирают
статистику. Раньше они жили только на хостинге и не были доступны агенту;
теперь исходники есть в репозитории и аудируемы.

## Состав

| Файл | Назначение | Запуск |
| :--- | :--- | :--- |
| `post_cron.php` | публикация approved-постов MAX по слотам; читает посты из GitHub (`main`), состояние — `/0s3/blogger-data/state/` | `php post_cron.php` (cron) либо web-обёртка `post_web.php?s=<secret>` (DRY) / `&go=1` (реальный запуск) |
| `stats_cron.php` | снимки подписчиков/просмотров 4 каналов в `/0s3/blogger-data/stats/` | `php stats_cron.php` или включается `post_cron.php` в 07:45 |
| `tg-relay.php` | релей Telegram (-api.telegram.org недоступен из локальной среды) | web |

Файлы синхронизированы с хостингом 22.11.2026: `post_cron.php` взят из
текущей удалённой версии (с гейтами `publish_time`/`gate_time` и включённым
`administrator`), `stats_cron.php` совпадает с удалённой копией байт-в-байт.
Токены в репозитории отсутствуют: скрипты читают их с хостинга из
`/0s3/blogger-data/<slug>_token.txt` (вне webroot). **Не добавлять токены и
`ftp-creds.json` в git.**

## na100 на хостинге (этап 1)

Решением владельца 28.11.2026 утренний na100 переносится на хостинг полностью,
включая генерацию текста через Cloudflare Workers AI (`@cf/openai/gpt-oss-120b`).
Прежнее решение 11.11 «LLM в пайплайн не подключать» отменено.

Уже развёрнуто на хостинге:

- `na100_config.php` — конфиг; секреты читаются из `/0s3/blogger-data/`
  (`cloudflare-token.txt`, `cloudflare-account.txt`), в репозитории их нет;
- `na100_validator.php` — проверка текста по `AGENTS.md §0` (подмножество
  `shared/format_core.py`); CLI: `php na100_validator.php <файл>`.

Следующие этапы: `na100_prepare.php` (06:30, RSS + ИИ + обложка GD) и
`na100_publish.php` (07:30, публикация и state), затем cron и зеркало в GitHub.

## Слоты

Единственная таблица слотов — `docs/scheduled-tasks.md`. Хостинг-кроны:
`09:00` вт/чт — `administrator`, `12:00` — кросс-пост `ainow` (Format 1),
`19:30` — `zabava`, `20:00` — `catden` (единственный слот; утренний 07:32
отменён гейтом `gate_time`), `21:30` — посты плана `ainow`;
статистика — `07:45`. na100 в `post_cron.php` не публикуется: агент готовит
выпуск утром и отправляет его прямо в канал. Локальные задачи Windows удалены
полностью: включать `07:15` нельзя — был бы дубль с хостингом.

**Format 1** — кросс-пост `ainow` в 12:00 МСК: пост канала `ainow` с явно
указанным `publish_time` в front matter, который хостинг публикует в утренний
слот вместо слота по умолчанию `21:30`. Это не отдельный формат текста:
пост соблюдает `AGENTS.md §0` FORMAT CORE v1; термин «Format 1» описывает
только время и способ публикации.

## DRY-режим

`post_cron.php` в web-контексте без `go=1` работает в DRY: читает посты,
прогоняет гейты и печатает решение, **не отправляя** сообщения. Команда
`php post_cron.php` из cron — реальная публикация. Перед ручным запуском
всегда проверять `status` поста: `published` повторно не отправляется.

## Синхронизация

Правки хостинг-скриптов делаются в этом каталоге, затем заливаются на Beget
`post_cron.php` → `/0s3/blogger-cron/post_cron.php` с бэкапом. Локальные
скрипты заливки и Moscow-копии живут в gitignored `local/` и в репозиторий
не попадают.

Правила формата постов в PHP-кроне — подмножество единого движка
`shared/format_core.py`; при расхождении источник истины — `AGENTS.md §0`.

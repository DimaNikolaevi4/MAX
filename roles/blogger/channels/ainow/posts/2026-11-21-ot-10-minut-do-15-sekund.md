**От 10 минут до 15 секунд: как ускорить ИИ-агента**

Вы просите ИИ-агента в Cursor, OpenCode или Copilot: «Посмотри папку `E:\github\project` и синхронизируй репозитории». В ответ — десять минут «размышлений», Linux-команды (`&&`, `head`, `2>/dev/null`) в Windows PowerShell, ошибки кодировки и сломанный скрипт, который агент тут же пытается «починить».

Проблема не в «глупости» модели, а в архитектуре взаимодействия. Когда вы даёте агенту только «локацию», он вынужден гадать: какая ОС, какие пути, какие правила. Эта спираль галлюцинаций сжигает токены и время — про цену такой работы мы [уже писали](https://max.ru/channel_ainow/AaH5cIdELNk).

Наша система сократила рутинные задачи с 10 минут до 15 секунд. Вот три шага.

**Шаг 1. Паспорт машины**
Агент не должен сканировать весь диск `C:` или `E:`, чтобы понять, где он. Дайте ему один файл — источник истины. Создайте `machine_profile.json` в корне проекта:

{
"os": "Windows",
"shell": "powershell",
"root_dir": "E:/github/",
"repos_to_sync": ["MAX", "kalendar", "avtosite"],
"plans_dir": "E:/github/kalendar/plans/"
}

Теперь агент читает файл за доли секунды и знает точные пути и список задач.

**Шаг 2. Анти-галлюцинационный триггер**
Создайте в корне репозитория файл правил `AGENTS` — конституцию для ИИ. Внутри не пожелания, а жёсткие запреты:

1️⃣ **Запрещено** использовать синтаксис Linux (`&&`, `||`, `head`). Только PowerShell 5.1 (`;` или новые строки).
2️⃣ **Запрещено** писать внутренний монолог («Сейчас я проверю…», «Ой, ошибка кодировки, попробую base64…»). Только финальный результат.
3️⃣ **Запрещено** создавать временные `.ps1` в `AppData\Temp` или `C:\Users\Public\`. Команды — прямо в консоли.
4️⃣ При вставке переменной перед двоеточием используйте `${имя_переменной}`, чтобы не ломать парсинг путей.

**Шаг 3. Готовые скрипты вместо «придумай сам»**
Самая большая ошибка — просить: «Напиши скрипт для синхронизации». Агент добавит лишнее. Вместо этого в нём лежит готовый протестированный блок, который агент копирует и выполняет. Например, безопасный `git pull`, обходящий ошибку `unstaged changes`:


$profile = Get-Content "E:\github\kalendar\docs\ai-orchestration\machine_profile.json" | ConvertFrom-Json
foreach ($repo in $profile.repos_to_sync) {
    $path = Join-Path "E:\github" $repo
    if (Test-Path $path) {
        Set-Location $path
        git stash | Out-Null
        git pull --rebase origin main | Out-Null
        $pullCode = $LASTEXITCODE
        git stash pop | Out-Null
        if ($pullCode -eq 0) { Write-Output "${repo}: OK" }
        else { Write-Output "${repo}: ОШИБКА" }
    }
}

**Результат: до и после**
**Было (10 минут).** Агент генерирует команду с `&&`, получает `ParserError`, паникует, создаёт файл в `C:\Users\Public\`, теряет кодировку UTF-8 и пишет длинный отчёт о том, как «старался исправить». Нужных данных нет.

**Стало (15 секунд).** Вы пишете триггер: «смотри `E:\github\kalendar`». Агент молча читает файл правил, берёт пути из `machine_profile.json`, выполняет готовый скрипт и выдаёт таблицу задач. Ни воды, ни галлюцинаций.

**Главный вывод**
ИИ-агент — не волшебник, а высокоскоростной исполнитель. Чем меньше пространства для «творчества» в технических задачах, тем точнее, быстрее и дешевле он работает. Жёсткий контекст, готовые скрипты и запрет на внутренний монолог — формула автопилота.

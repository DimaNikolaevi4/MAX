# Черновики выпусков na100 (в git, синхронизируются на все машины)

> Решение владельца 12.11.2026: проверяемая атрибуция — только в черновиках;
> на публикацию она не попадает и на последнем этапе публикации обязательно
> вычищается. Расчёт лимита 4000 знаков ведётся без атрибуции.
> Правила — `docs/techdigest-methodology.md` §7а, `style.md` канала (Лимиты).

## Что здесь лежит

| Файл | Кто пишет | Что содержит |
| --- | --- | --- |
| `<дата>-draft.json` | `digest_build.py` (06:30, сам коммитит и пушит) | шортлист кандидатов со скорингом, полные ссылки (`link`) на материалы каждой новости |
| `<дата>/image-meta.json` | агент при поиске обложки | источник, автор, лицензия, URL фото, URL страницы правил, флаг «документальное/иллюстрация» (формат — `docs/techdigest-methodology.md` §7) |

## Что остаётся в `local/digest/` (не в git)

Runtime-файлы машины-сборщика: `raw-<дата>.json` (сырые фиды),
`last_7_days.json` (память новизны), `fallback_state.json` (состояние пула
фонов), обложки `cover-*.png` (тяжёлые файлы — в git не хранятся).

## Проверяемость

Атрибуция новости в посте — короткой текстовой вставкой («по данным SCMP»,
«сообщают источники») или подписью изображения («Фото: …» / «Иллюстрация: …»,
без URL). Полный URL для проверки — здесь, в черновике за дату выпуска.
`publish_post.py` для na100 блокирует публикацию, если в тексте есть любая
ссылка, кроме CTA на канал.

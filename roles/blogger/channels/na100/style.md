# Стиль канала na100 — ежедневный техно-дайджест

> Формат утверждён протоколом перезапуска (`docs/na100-relaunch-2026-11-10.md`,
> 10.11.2026). Канал: **«Новости технологий ИИ, нейросетей и инноваций»**
> (ссылка прежняя — https://max.ru/channel_na100; до 12.11.2026 канал
> назывался «Новости мира техники») — название, описание и
> закреп применены в MAX 10.11.2026 (чистый лист: старые посты удалены,
> закреплён пост-анонс перезапуска). Полные детали — вопрос №5 протокола..

## Контекст

- Канал: https://max.ru/channel_na100 (chat_id в `local/tokens.json`, slug `na100`).
- Формат: **ежедневный техно-дайджест** — 5 технологических новостей
  (1 Россия + 1 Китай + 3 мира), простым языком с юмором.
- Эксперимент: 1 месяц с даты первого выпуска. Норма — 1 выпуск в день,
  выходные включены; пропуск дня допустим и не требует объяснений.
- Публикация в автопилоте, без предварительного ревью. Правки — постфактум,
  фактические ошибки исправляются публичным уточнением, а не тихой правкой.
- Объём эксперимента и правила оценивания — в протоколе перезапуска.

## Обязательный формат выпуска

1. **Строка-хук (40–60 знаков):** главная интрига дня, без кликбейт-обмана.
   Не считать её заголовком первой новости.
2. **Пять новостей**, у каждой:
   - Жирный подзаголовок с номером, например
     `1️⃣ **Автоматизированное проектирование гибридных сетей**`.
     Гео-надписи «Россия:» / «Китай:» / «Мир:» и эмодзи-флаги/глобус
     не используются (решение 11.11.2026, вечер).
   - **Что случилось** — 1–2 предложения, только факты.
   - **Почему важно** — 1–2 предложения, без преувеличений.
   - Одна шутка на выпуск размещается у той новости, где она получается
     естественной; не обязана быть у каждой.
3. **Короткий итог** — 1–2 строки, что день в целом показал.
4. **CTA** — призыв подписаться на сам канал (не на ainow; фразы из
   `cta-phrases.json`, без повторов). Пример нижнего блока:
   `> **Подписывайтесь на [Новости технологий ИИ, нейросетей и инноваций](https://max.ru/channel_na100)** — <фраза>`.
5. Изображение прикрепляется к посту: фото/иллюстрация по цепочке поставки
   (раздел «Картинки») или брендированная заставка
   (`python roles/blogger/tools/digest_cover.py`); маркировка
   «Фото:» / «Иллюстрация:» обязательна.
6. **Стандарт заставок (утверждён владельцем 11.11.2026, вечером)** —
   один рецепт для всех изображений канала, зафиксирован в
   `cover-method.md` («Стандарт обложек na100»): мачхед «время →
   Новости ИИ / и технологий → акцент-дата цветом → Ежедневный
   утренний обзор», авто-тема по фону, авто-вуаль на светлых фонах
   (0.55), панель «ФОРМАТ» с темами 01–05 в порядке подачи.
   Фото-инструмент — `digest_cover_photo.py` (дефолты уже стандартные,
   вызов: `--bg <фон> --out <файл> --items "…" --over "<время>"`);
   при простое цепочки поставки — уровень 4 «фон из пула» ниже.

## Подача: нумерация и перемешивание (решение 11.11.2026)

- **Только нумерация** (решение уточнено 11.11.2026, вечер: эмодзи-флаги
  и глобус убраны). Гео-надписи «Россия:» / «Китай:» / «Мир:» из
  заголовков убраны — региональный состав остаётся на уровне отбора
  (см. «Скоринг и отбор»), читатель видит просто 5 пронумерованных новостей.
- **Перемешивание перед каждым выпуском.** Порядок подачи 5 новостей
  задаётся `random.shuffle` на этапе сборки: сегодня первой может выйти
  российская новость, завтра — китайская. Состав выпуска (1 РФ + 1 Китай +
  3 мира) при этом не меняется — меняется только порядок.
- Пункты панели «ФОРМАТ» на заставке берутся из выпуска **в том же
  перемешанном порядке** (нумерация 01–05 на обложке — это порядок подачи,
  не география).

## Читаемость — четыре слоя проверки (введено 11.11.2026)

Повод: ручная правка выпуска №2 — «поставщики памяти двигают цены» →
«поставщики памяти и двигают цены». Грамматически корректная фраза, которая
спотыкается при чтении; LanguageTool такое не ловит. Четыре слоя
(слои 1–3 — автоматика, действуют во всех каналах: AGENTS.md, §5а+):

**Слой 1 — LanguageTool (публикатор, блокирует).** Орфография, пунктуация,
грамматика. Текст режется на куски ≤900 знаков (публичный API отдаёт таймаут
на длинных текстах — так утренние проверки молча пропускались). Ложные
срабатывания на техно-сленг и имена — в канальном списке
`spell-ignore.json` (добавлять только по факту срабатывания, корнями слов).

**Слой 2 — эвристики читаемости (`shared/readability.py`, публикатор,
только WARN):** длинное предложение (>30 слов), 3+ однородных без союза
«и»/«или», повтор слова в предложении, канцелярит, пробелы/пунктуация,
непарные кавычки и скобки. Не блокируют публикацию; WARN из отчёта
`local/publish-<канал>.txt` читается постфактум.

**Слой 3 — сканер штампов (`shared/lexicon.py` → пакет `ru-humanizer`,
публикатор, только WARN).** Детектор канцелярита и AI-штампов
(github.com/ilyautov/humanizer-ru, MIT, локально): жёсткие запреты,
маркеры с позициями, номинальность (сущ./глаг. > 2,5 — прокси канцелярита),
«ровные абзацы». Пакет опционален: не установлен — публикатор работает без
него. Легальные для формата канала категории (нумерация 1️⃣–5️⃣, жирные
подзаголовки) — в `lexicon-ignore.json` («Обвязка чата»); жанр — `news`.

**Слой 4 — финальная вычитка владельца, постфактум (решение 11.11.2026).**
Выпущенные посты вычитывает владелец сам и правит прямо в канале через
клиент (штатный механизм правок постфактум); агент синхронизирует такие
правки в md-файл поста с пометкой `edited_at`. Чек-лист ниже агент
выполняет при сборке выпуска до `approved` — чтобы правок постфактум
было меньше:
- **Однородные члены.** При перечислении субъектов/объектов проверять союз:
  «поставщики памяти двигают цены» → «поставщики памяти и двигают цены»;
  три и более однородных — обязательно «и» перед последним.
- **Цепочки родительного падежа** 3+ подряд («решения совета директоров
  компании») — перестроить («решение совета директоров компании» →
  «решение, которое принял совет»).
- **Ритм.** Два предложения подряд с 25+ словами — разбить. После длинного
  идёт короткое. Абзац «спотыкается» вслух — переписать.
- **Повторы.** Одно слово 2+ раза в абзаце (кроме терминологии выпуска) —
  заменить или перестроить.
- **Канцелярит запрещён** (список в `shared/readability.py`) — тон «просто,
  по-домашнему»; «является» → «это», «осуществляет» → глагол действия.
- **Числа и валюты единообразно:** `$1,4 трлн`, `1300–8000 юаней`,
  `$29,99`.
- **Цензура смысла запрещена:** правка читаемости не должна добавлять
  уверенности там, где источник говорит «слухи»/«по данным» — модальность
  оговорок сохраняется.

Слои 1–3 — автоматика на публикации (все каналы); слой 4 — вычитка
владельца постфактум в канале, чек-лист агент выполняет при сборке
выпуска до статуса `approved`. Правки постфактум остаются штатным
механизмом.

## Лимиты

- **≤ 4000 знаков — жёсткий потолок** на весь пост. Бюджет: хук + итог + CTA
  + подзаголовки ≈ 700–800 знаков, на новость ≈ 600–650 знаков.
- **Расчёт до 4000 ведётся БЕЗ атрибуции** (решение владельца 12.11.2026):
  полная проверяемая атрибуция — только в черновике выпуска
  (`digests/<дата>-draft.json`, лежит в git), на публикацию она не
  попадает; на последнем этапе публикации текст обязательно вычищается —
  публикатор блокирует любую ссылку, кроме CTA на канал. Скобочные
  врезки-источники со ссылками («(полный обзор — на Хабре)») в посте
  запрещены; короткие текстовые указания («по данным SCMP», «сообщают
  источники») и подписи изображений («Фото: …» / «Иллюстрация: …»,
  без URL) — остаются.
- При переполнении **детерминированно** дропается низкобалльная новость
  «мира» (не Китай-замена) — выпуск выходит с 4 новостями и честной пометкой
  «в мире сегодня тише». Ниже 4 новостей выпуск не публикуется.
  LLM-сжатие текста запрещено: сокращение теряет факты и оговорки.
- Воздух (`\n\n`) между блоками; маркеры литеральные `—` / `•` / 1️⃣
  (MAX не рендерит markdown-списки — см. `roles/blogger/channels/ainow/style.md`, раздел 6).

## Скоринг и отбор

- Формула: `свежесть×0.3 + влияние×0.4 + новизна×0.2 + авторитет×0.1`,
  порог 5.0; регион с пустым результатом считается «тихим».
- Состав: 1 РФ + 1 Китай + 3 мира. Если Китай пуст — 1 РФ + 4 мира с пометкой
  «в китайском сегменте тихо».
- Конфиги: `roles/blogger/config/major_players.json`, `stop_list.json`,
  список фидов — `roles/blogger/config/techdigest_feeds.json`.
- Память новизны: `local/digest/last_7_days.json` (runtime, в git не идёт) —
  новость, показанная в течение 7 дней, повторно не выходит.
- Калибровка порога — после первых 10 выпусков.

## Юмор и этика

- Стоп-лист тем для юмора — жёсткий и не обсуждается: жертвы, болезни,
  религия, национальность, внешность, уязвимые группы. Юмор — про технологии
  и отрасль, не про людей в беде.
- Тон: просто, по-домашнему, понятным языком с лёгкой иронией — наследуется
  от прежнего стиля канала.

## Картинки — политика заимствования v2 (улучшена 10.11.2026 по итогам выпуска №1)

Основа — шаги 1–2 методологии + поправки протокола
(`docs/na100-relaunch-2026-11-10.md`). Улучшения после первого выпуска:
три уровня качества фото, честная маркировка, релевантность и этика стоков.

**Шаг 1. Проверка права (whitelist доменов, `config/image_sources.json`):**
- домены агентств (Reuters, AP, AFP...) и стоков без лицензии — в
  deny-листе, без исключений;
- RSS-теги `<copyright>` и `creativeCommons:license` — слабый сигнал: без
  подтверждённого основания (страница правил / лицензия через API) картинку
  не берём;
- пресс-центры попадают в `allowed` вручную, после явного разрешения на
  странице правил; копия/скриншот страницы — в `local/digest/<дата>/`;
- список ведётся вручную; стартовый `allowed` может быть пустым.

**Шаг 2. Извлечение кандидата (только после шага 1):**
- `<enclosure type="image/*">`, `media:content` / `media:thumbnail`,
  fallback — первый `<img>` из HTML-описания статьи;
- кандидат ≠ разрешение: без шага 1 не используется.

**Цепочка поставки (порядок приоритета; одно фото на выпуск, сюжет — любая
из новостей выпуска):** выбирается лучшая пара «сюжет × фото» — релевантность
снимка × вес новости; фото «ради галочки» к слабому сюжету не тянем:
1. **Документальное фото** — Wikimedia Commons через API (`extmetadata`),
   только CC0 / CC BY / CC BY-SA; в посте «Фото: Wikimedia Commons /
   <автор> (<лицензия>)».
2. **Тематическая иллюстрация** — открытые фотобанки Unsplash / Pexels /
   Pixabay (их лицензии разрешают переиспользование, включая коммерческое;
   доступ по API, атрибуция — автор + сервис). В посте обязательно честное
   «Иллюстрация: Unsplash / <автор>», чтобы читатель не принимал сток за
   документальный снимок события.
3. **Кандидат из RSS статьи** — только если домен в `allowed`
   (`config/image_sources.json`, добавляется вручную с `credit_type`);
   подпись по `credit_type` домена: `documentary` → «Фото: пресс-служба
   <компании>», по умолчанию `illustration` → «Иллюстрация: <домен>».
4. **Фон из пула канала** (решение 11.11.2026) — случайное изображение
   из `roles/blogger/channels/na100/images/fallback/` (материал владельца)
   + брендированная плашка `digest_cover_photo.py`. Выбор и разбор фона:
   `py roles/blogger/tools/pick_fallback.py` (не повторяет предыдущий
   выбор; тема/цвета уже разобраны в `fallback_images.json`, но обложка
   пересчитывает их сама, `--theme auto`). Атрибуция не нужна: это
   заставка на фоне из пула, а не чужое фото.
5. **Брендированная заставка** `digest_cover.py` — штатный fallback, если
   пул пуст; раскладки поверх готовых фонов (картинка/видео пользователя)
   и все грабли — по методике:
   `roles/blogger/channels/na100/cover-method.md`
   (инструменты `digest_cover_photo.py`, `digest_cover_video.py`).

**Тайм-бюджет поиска (введено 11.11.2026):** поиск без «поиска ради поиска»:
Commons ≤ 90 сек (2–3 варианта запроса), фотобанки ≤ 60 сек (1 запрос),
RSS allowed ≤ 30 сек (домен не в allowed — шаг пропускается мгновенно);
суммарно ≤ 3 мин на выпуск. «Не нашли» — штатный исход: заставка, поиск не
продлевается. Дерево решений, схема `credit_type` и формат
`image-meta.json` — `docs/techdigest-methodology.md`.

**Улучшение 1 — честность маркировки.** Две категории не разрешается
смешивать: документальное фото подписывается «Фото:», тематическая
иллюстрация — «Иллюстрация:». Читатель всегда отличает событие от стока.

**Улучшение 2 — релевантность важнее наличия.** Картинка обязана
тематически соответствовать сюжету, который она иллюстрирует. Если
подходящего снимка нет или релевантность сомнительна — заставка, фото
«ради галочки» не тянём. Подпись фото всегда привязывает его к конкретному
сюжету выпуска.

**Улучшение 3 — этика стоков.** Сюжеты о конкретных людях (скандалы,
болезни, аресты, жёсткий список из стоп-листа юмора) не иллюстрируются
портретными стоками со свободных фотобанков — чей-то стоковый портрет
не должен стоять рядом с обвинением. Для таких сюжетов допустимы только
нейтральные предметные кадры (здание, серверная, чип) из Commons или
заставка.

**Улучшение 4 — учёная трасса.** К каждому изъятому изображению в
`roles/blogger/channels/na100/digests/<дата>/image-meta.json` пишется:
источник, автор, лицензия, URL страницы фото, URL страницы правил (для
пресс-центров), флаг «документальное / иллюстрация». Учёт — обязательная
часть сборки, не «по желанию».

**Fallback и критерий:** заставка обеспечивает критерий «100% выпусков
с изображением»; доля выпусков с фото — метрика, ни на что не влияет.

**Атрибуция:** формат как выше; URL — в JSON черновика (решение по
вопросу №4 протокола).

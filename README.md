# MAX — методика публикации в каналы мессенджера MAX

Репозиторий — это **методика ведения нескольких каналов в мессенджере MAX** через
Bot API. Проект спроектирован так, чтобы с ним одинаково комфортно работал
любым ИИ-агентом: локальным (OpenCode и подобные) или онлайн. Агент готовит
посты, изучает архив опубликованных материалов для соблюдения стиля канала,
отправляет их через Bot API и коммитит результат в git.

## Карта репозитория

```
MAX/
├── AGENTS.md               # Методика и правила для ИИ-агентов (главный файл)
├── README.md               # Этот файл (для людей)
├── docs/
│   ├── bot-setup.md          # Пошаговая настройка бота с нуля (проверено на практике)
│   └── agent-onboarding.md   # Вход для нового ИИ-агента (что читать, чего не делать)
├── bin/
│   └── post.php            # CLI-скрипт отправки поста (PHP 8.1+, расширение curl)
├── config/
│   └── channels.json       # Реестр каналов (slug, название, cta_label/cta_url; БЕЗ токенов)
├── channels/
│   └── <slug>/             # Отдельная папка на каждый канал
│       ├── style.md        # Описание стиля канала (тон, темы, оформление)
│       ├── cta-phrases.json# Реестр фраз призыва (CTA) — не повторяются между постами
│       ├── proofread.md    # Статус вычитки/правок (если есть)
│       └── posts/          # Все посты канала: черновики и опубликованные
└── local/
    ├── tokens.example.json # Шаблон файла с токенами
    └── tokens.json         # Реальные токены (НЕ коммитится, в .gitignore)
```

## Формат поста

Каждый пост — отдельный Markdown-файл с front matter:

```markdown
---
channel: ainow            # slug канала (должен совпадать с папкой)
status: draft             # draft -> approved -> published
format: markdown          # markdown | html
notify: true              # push-уведомления (для каналов должно быть true)
disable_link_preview: false
published_at: null        # заполняется скриптом после отправки
message_id: null          # заполняется скриптом (mid ответа API)
channel_id: null          # заполняется скриптом (chat_id)
url: null                 # заполняется скриптом (публичная ссылка на пост)
---

Текст поста...
```

 Статусы (жизненный цикл):
- `draft` — черновик, публике не виден, бот его **не отправит**;
- `approved` — человек подтвердил публикацию, бот может отправлять;
- `published` — отправлено, файл хранится как архив с ID и ссылкой.

## Как опубликовать пост

На машине/хостинге с PHP 8.1+ и расширением curl:

```bash
php bin/post.php channels/ainow/posts/2026-10-29-brauzernye-aiagenty-ustupayut-rabochemu-stolu.md
```

Опции:

```bash
php bin/post.php <файл> --dry-run          # показать payload, не отправляя
php bin/post.php <файл> --chat-id=123456   # временно переопределить chat_id
```

Переменные окружения:

- `MAX_TOKENS_FILE` — путь к файлу токенов (по умолчанию `local/tokens.json`);
- `MAX_API_BASE` — адрес API (по умолчанию `https://platform-api2.max.ru`);
- `MAX_CA_CERT` — путь к сертификату Минцифры, если хостинг его требует;
- `MAX_INSECURE=1` — отключить проверку TLS (только для отладки, не рекомендуем).

## Правила безопасности

1. **Токены и ключи никогда не попадают в git.** Храним локально в `local/tokens.json`
   (скопируйте из `local/tokens.example.json`), путь закрыт `.gitignore`.
2. Для GitHub Actions (будущий планировщик отложенных публикаций) токен кладём в
   Secrets репозитория, а не в файл.

## Ограничения API MAX (актуально на момент создания)

- Домен: `https://platform-api2.max.ru`, токен в заголовке `Authorization`.
- Лимит: **не более 2 сообщений в секунду** в один чат/канал.
- Лимит редактирования — тот же: **не более 2 сообщений в секунду** в один
  канал. Учитывайте это при массовой проверке и правке старых постов.
- Лимит текста поста: **4000 символов**.
- В каналы отправка только с `notify = true` (или без параметра).
- Отложенной публикации в API нет — её можно достичь планировщиком (cron /
  GitHub Actions). В этой версии проекта планировщик не реализован.

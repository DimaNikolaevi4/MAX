# ainow: редакционная методика канала «AI»

> Введено 20.11.2026 по разбору 14 последних публикаций и `style.md` канала.
> Формат (`roles/blogger/channels/ainow/style.md`, правила 1–7) не меняется —
> меняется дисциплина его исполнения и добавляются два формата подачи.

## 1. Что уже работает (не трогаем)

- **Честность про ограничения** — главный актив канала: лимиты, блокировки, приватность.
- **Вопрос в конце** — 13 постов из 14.
- **Практика вместо пресс-релизов**: разборы инструментов, промпты, порядок шагов.
- **Воздух**: короткие абзацы, один блок — одна мысль.

## 3. Обязательные форматы подачи

### 3.1 Блок «⚠️ Где это сломается» — в каждом обзоре инструмента
1–3 пункта, сразу после разбора. Это не «минусы ради баланса», а конкретика:
лимит, блокировка, кривой экспорт, требования к железу.

### 3.2 Промпт-блок — если в посте есть промпт
Один промпт на пост, оформляется цитатой (`> `), как блок данных;
моноширинный для промпта не используем:

```
Сделай структуру презентации на 10 слайдов по теме [ТЕМА]. Для каждого слайда:
1) заголовок, 2) три буллета с фактами, 3) идея визуализации.
```

## 4. Правила вёрстки (жёстко)

- **Списки только литерально:** «— » для пунктов, «1️⃣ 2️⃣ 3️⃣» для шагов.
  `* `, `- `, `1. ` и таблицы `| |` в MAX остаются символами — это брак.
- **Подзаголовки разделов — жирной строкой**, не `###`: MAX заголовки съедает
  в тексте поста, иерархия теряется.
- **Бюджет жирного: ≤6 выделений внутри абзацев** (подзаголовки не считаются).
  Выделяем только названия инструментов, цифры, названия блоков.
- **Перелинковка: 1–2 ссылки** на прошлые посты канала — в абзаце по теме,
  не отдельным блоком (правило 7 `style.md`).
- **Длина:** до 4000 (лимит API), комфортно — до 3600.
- **Один «выход» на пост:** промпт, чек-лист или порядок шагов. Нет выхода —
  пост переделывается, а не публикуется.

## 5. Тон

- Обращение на «вы», практично, без хайпа.
- Вопрос в конце — конкретный, по теме поста: не «а как вы?», а «сколько раз
  за неделю вы ловили „The server is busy"?».
- Никаких выдуманных тестов: цифры либо из источника с атрибуцией, либо своё
  честное «на трёх задачах вышло так» с описанием, как проверяли.

## 6. Чек-лист перед публикацией

```
py roles/blogger/tools/ainow_polish.py <пост> --check
```

Проверяет: длину, литеральные списки и `###`, бюджет жирного, перелинковку
(1–2 ссылки), CTA-цитату предпоследним блоком, вопрос последним, картинку, наличие «выхода»
(промпт/чек-лист/шаги) и предупреждений об ограничениях.

## 7. Оценка эффекта

Аудитория пока небольшая, статистика шумит. Критерии качественные:
реакция владельца при вычитке, комментарии под вопросом, число правок после
публикации, число пересылок (видно в статистике поста). Просмотры собираем,
но решения принимаем не по ним.

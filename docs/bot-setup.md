# Настройка бота MAX с нуля (проверенная пошаговая инструкция)

Инструкция составлена по факту настройки бота **AI Now** (`@se14808890_bot`)
для канала **AI** (`https://max.ru/channel_ainow`), 28.10.2026. Подходит для
любого нового канала по той же методике.

## 0. Требования

- Профиль на [business.max.ru](https://business.max.ru/self) с верификацией.
  Доступно: юрлицам, ИП и **самозанятым** — резидентам РФ.
  Обычное физлицо без статуса создать бота не может.
- Количество ботов ограничено тарифом профиля (у самозанятого — 2 бота).
  Поэтому **одного бота выгодно использовать на несколько каналов** (см. раздел 7).

## 1. Создание бота

1. business.max.ru → **Чат-боты** → **Создать**.
2. Заполните: название, никнейм (например `se14808890_bot`), описание, логотип.
   Название бота подписчики почти не видят: посты в канале публикуются без
   подписи автора. Но выбирайте осмысленное имя — оно всплывёт, если бот
   ответит в комментариях.
3. Бот уходит в статус **«На модерации»**. Пока модерация не пройдена:
   - токен уже работает (можно проверить `GET /me`);
   - но бота **нельзя найти в поиске и добавить в канал** — будет «Контакт не найден».
4. Уведомление о прохождении модерации приходит в диалог с ботом
   **«MAX для бизнеса»** в мессенджере.

## 2. Токен

- На business.max.ru: карточка бота → **⋮** (или стрелка) → **Настройки** →
  скопировать токен.
- Либо в мессенджере: бот **«MAX для бизнеса»** → кнопка **«Получить токен»**.
- Токен храним ТОЛЬКО локально: `local/tokens.json` (см. `local/tokens.example.json`).
  В git он не попадает — путь закрыт `.gitignore`.

## 3. Начать диалог с ботом (важный шаг!)

**Найдите бота в поиске мессенджера MAX и начните с ним диалог** (кнопка
«Старт»/«Начать»). Без этого шага дальнейшие действия с ботом могут не работать,
а событие `bot_started` — первое, что фиксирует платформа.

## 4. Добавление бота в канал и назначение администратором

Делается в мессенджере MAX (не на бизнес-портале):

1. Откройте канал → нажмите на его название → **Подписчики** →
   **Добавить подписчиков**.
2. В поиске введите никнейм бота (можно без `@`) или его имя.
   Если «Контакт не найден» — проверьте, что модерация пройдена, и что в
   настройках бота (⋮ → Настройки → **Приватность**) разрешено добавление
   в групповые чаты.
3. Назначьте бота **администратором**. Права:
   - **Писать посты** — обязательно;
   - Редактировать чужие посты, Удалять чужие посты, Закреплять посты —
     рекомендуется (нужны для правок и закрепов);
   - Добавлять и удалять подписчиков — по желанию;
   - **Назначать администраторов — НЕ нужно** (безопаснее не давать).

## 5. Получение chat_id канала

Готовой команды «покажи каналы бота» в API нет. `chat_id` приходит в событиях:

```
GET https://platform-api2.max.ru/updates
Authorization: <токен>
```

В ответе ищем событие `"update_type": "bot_added"` — в нём `chat_id` канала
(у каналов он **отрицательный**, например `-76964086179165`). Там же будет
`bot_admin_permissions_changed` со списком прав администратора.

Проверка канала: `GET /chats/{chatId}` — вернёт название, число подписчиков,
ссылку и описание. Вписываем `chat_id` в `local/tokens.json`.

## 6. Проверка работоспособности

```bash
# Информация о боте (должен вернуться HTTP 200 и JSON с is_bot: true)
curl -H "Authorization: <токен>" https://platform-api2.max.ru/me

# Информация о канале
curl -H "Authorization: <токен>" https://platform-api2.max.ru/chats/<chat_id>
```

Нюанс TLS: в изолированных средах (Node-песочницы, некоторые CI) возможна ошибка
`unable to get local issuer certificate`. Решения: системный `curl` (на Windows
использует хранилище сертификатов ОС), либо сертификат Минцифры через
`MAX_CA_CERT` (см. `bin/post.php`).

## 7. Один бот на несколько каналов

Бот может быть администратором **нескольких каналов одновременно** — у каждого
канала свой `chat_id`, а отправка идёт в конкретный канал по его `chat_id`
(`POST /messages?chat_id=...`). В `local/tokens.json` это выглядит так:

```json
{
  "ainow":  { "token": "ТОКЕН_БОТА", "chat_id": -76964086179165 },
  "second": { "token": "ТОКЕН_БОТА", "chat_id": -111111111111 }
}
```

Один и тот же токен в двух записях = один бот ведёт оба канала. Скрипт
`bin/post.php` сам выберет нужный `chat_id` по полю `channel` в front matter
поста. Лимиты (2 сообщения/сек на канал, 30 rps на API) это позволяют.

Либо можно завести отдельного бота на каждый канал — чуть чище с точки зрения
отзыва доступа, но лимит ботов ограничен тарифом.

**Цель:** посты catden выходят в 20:00 МСК. Время единое для всех дней (решение владельца).

**Ключевые точки:**

## 4. Задача B — Еженедельный цикл медиа на хостинге (четверг)

**Цель:** на хостинге в `/0s3/blogger-data/media/catden/<дата>/` лежат ровно нужные медиа для ближайших 11 дней вперёд; дублей и пропусков нет; отработавшие каталоги/файлы удалены.

**Выполнять каждый четверг (окно — 11 дней вперёд от даты выполнения/публикации, скользящее):**

1. **Определить окно:** ближайшие 10 календарных дней, на которые в плане есть публикации catden (использовать [docs/catden-media-manifest-2026-11-19-2027-01-18.md](catden-media-manifest-2026-11-19-2027-01-18.md) и/или фактические front matter постов в `roles/blogger/channels/catden/posts/` с датами окна). Источник истины по составу медиа на дату — front matter поста этой даты: `image_file` (одно) или `image_files` (альбом, разделитель `|`); пусто/отсутствует — медиа не требуется (кроме draft без медиа — пометка владельцу).
2. **Сверка «что уже залито» (до заливки):** получить список существующих каталогов/файлов в `/0s3/blogger-data/media/catden/` (и внутри каталогов дат окна) по FTP/SFTP/файловому менеджеру. Сопоставить с требуемым из п.1.
3. **Заливка недостающего:** докачать только отсутствующие файлы для дат окна (оригиналы — по путям из front matter, напр. `nev/posting/images/...`; машина знает локальное расположение/источник). Не дублировать уже присутствующие корректные файлы. Для альбомов — все файлы набора.
4. **Очистка после публикации:** удалить отработавшие медиа/каталоги дат `< сегодня` (и/или уже опубликованных дат, не нужных для превью/повторов) — чтобы хостинг не захламлялся.
5. **Контроль:** для каждой даты окна количество и имена файлов на хостинге соответствуют манифесту/front matter; для draft без медиа (праздничные 31.12/01.01/07.01, пока не заполнены) — зафиксировать как «ожидает медиа от владельца».

**Ключевые точки:** сверка обязательна до заливки; источник превью пятницы — хостинг, поэтому к пятнице медиа на ближайшие 10 дней (окно пятничной вычитки) должны быть в актуальном состоянии.

## 5. Задача C — Еженедельная вычитка в канал «календарь» (пятница)

**Цель:** владелец вычитывает ближайшие 10 дней публикаций catden в одном месте, видя контент в том виде, как он выйдет.

**Выполнять каждую пятницу (горизонт — ближайшие 10 дней):**

1. **Собрать подборку:** посты catden на ближайшие 10 дней в порядке публикации по [docs/catden-media-manifest-2026-11-19-2027-01-18.md](catden-media-manifest-2026-11-19-2027-01-18.md) / файлам `roles/blogger/channels/catden/posts/` (дата в имени файла).
2. **Содержимое:** **текст + медиа как будет публиковаться, без дат** (даты в превью не указывать).
   - Медиа для превью брать **с хостинга** (`/0s3/blogger-data/media/catden/<дата>/`), залитые в четверг.
   - Альбом (`image_files`) — приложить все вложения; одиночное `image_file` — одно вложение; без медиа — только текст.
   - Посты `status: draft` (напр. 31.12/01.01/07.01 до готовности) — включать текстом с явной пометкой, что медиа от владельца ещё не залито / пост не `approved`.
3. **Куда отправлять:** приватный канал «календарь» (MAX). Правило 2г `AGENTS.md`: ключ `calendar` в `local/tokens.json` (тот же бот, `chat_id` канала). Отправка: `POST https://platform-api2.max.ru/messages?chat_id=...` с `{"text": ..., "format": "markdown"}` и вложениями по upload-API — **без поля `notify`** (в каналах запрещено). `chat_id` из `local/tokens.json`, не угадывать.
4. **Ограничения:** ≤4000 символов текста на сообщение — при необходимости разбивать на несколько сообщений, сохраняя порядок и связку «пост + его медиа»; загрузка медиа — через upload-API (см. `roles/blogger/tools/publish_post.py`, разделы 5/8а AGENTS.md). Транспорт/TLS при необходимости — как в AGENTS.md (на Windows `MAX_HTTP=python` + `MAX_CA_CERT` при проблемах).
5. **Не путать с автокалендарём блогера:** `docs/blogger-calendar.md` — отдельный авто-отчёт (задача 07:20), руками не правится; пятничная вычитка — отдельные сообщения в канал `calendar`.

## 10. Известные ограничения / что проверять на месте

- Панель Beget может быть в режиме восстановления (crontab/FTP-списки частично недоступны в UI) — иметь обходной путь (файловый менеджер/SSH/SFTP/FTP).
- FTP-сервер (наблюдалось): `mitiba.beget.tech`; видимый аккаунт `mitiba_crossbot` → `/0s3/public_html` (не покрывает `/0s3/blogger-data/...`) — для медиа нужен аккаунт/доступ к `/0s3/blogger-data`.
- Sprutio file manager — тяжёлый JS-интерфейс; при автоматизации браузером может быть недоступен для снапшотов — предпочтительнее прямой файловый доступ (SFTP/SSH/FTP).
- Локальные источники изображений (`nev/posting/images/...`) в git могут отсутствовать — брать из известного машине хранилища оригиналов.
- TLS/API нюансы — по `AGENTS.md` разделы 5 и 8а (при необходимости `MAX_HTTP=python`, `MAX_CA_CERT=local/russian_ca_bundle.pem`). Пятничная отправка в `calendar` — `POST /messages` без `notify`.

## 2. Режим «максимальный автомат» (решение владельца 18.11.2026)

- **Без надобности владельца не беспокоим.** Операционный цикл идёт по расписанию; вмешательство владельца — только вычитка/правки в канале «календарь» (и подготовка медиа для праздничных черновиков, где требуется его материал).
- **Публикация по графику:** посты `approved` с наступившей датой выходят автоматически в 20:00 МСК (хостинг). Если владелец **не внёс правки** после вычитки в «календаре» — публикация идёт по графику без дополнительного подтверждения.
- **Если владелец внёс правки в «календаре»** — агент вносит соответствующие правки в файл поста (и при необходимости в текст/медиа на хостинге для ещё не вышедших дат), синхронизирует репозиторий; далее пост публикуется по графику в актуальном виде.
- **19.11** — согласовано. **20.11** — на вычитке в «календаре» (кандидат отправлен 18.11). Далее все даты после пятничной вычитки живут по циклу п. 3–4.

## 3. Еженедельный цикл

### Четверг — медиа на хостинг (окно 11 дней вперёд, скользящее)

**Цель:** на хостинге `/0s3/blogger-data/media/catden/<дата>/` лежат ровно нужные медиа для ближайших 11 дней; дублей и пропусков нет; отработавшее удалено.

1. **Окно:** ближайшие 11 дней, на которые в плане есть публикации catden (по манифесту/front matter постов окна). Источник истины по составу медиа — front matter поста даты: `image_file` / `image_files` (через `|`); пусто — медиа не требуется (draft без медиа — пометка «ожидает медиа от владельца»).
2. **Сверка до заливки (обязательно):** получить список каталогов/файлов в `/0s3/blogger-data/media/catden/` (и внутри дат окна). Сопоставить с требуемым, чтобы **не дублировать** и **не пропустить**.
3. **Заливка:** докачать только отсутствующие файлы для дат окна (оригиналы по путям front matter / из известного хранилища). Для альбомов — все файлы набора.
4. **Очистка после публикации:** удалить отработавшие медиа/каталоги дат `< сегодня` (и/или уже опубликованных, не нужных для превью).
5. **Контроль:** для каждой даты окна состав на хостинге соответствует манифесту/front matter. К пятнице медиа на 10 дней пятничной вычитки должны быть в актуальном состоянии (источник превью — хостинг).

**Ограничения:** требуется доступ к хостингу (FTP/SFTP/SSH/файловый менеджер Beget) и оригиналы медиа. На машине, где `nev/posting/images/` отсутствует, заливка возможна только из внешнего хранилища/через хост-доступ.

### Пятница — итоговые посты на вычитку в «календарь» (окно 10 дней)

**Цель:** владелец вычитывает ближайшие 10 дней в одном месте и видит контент как будет публиковаться.

1. **Подборка:** посты catden на ближайшие 10 дней в порядке публикации (по манифесту/файлам постов).
2. **Подготовка текста (на автомате, перед отправкой):** стилистическая правка/шлифовка через ИИ (агент) + **4 слоя вычитки**:
   - **Слой 1 — язык (LanguageTool, блокирующий):** орфография/пунктуация/грамматика (как в `publish_post.py` / §5а+ AGENTS.md). Блокеры устраняются до отправки.
   - **Слой 2 — эвристики читаемости (`shared/readability.py`, WARN):** длинные/однотипные предложения, повторы, канцелярит — по возможности править.
   - **Слой 3 — лексика/штампы (`shared/lexicon.py`, ru-humanizer при наличии, WARN):** с учётом канальных исключений (см. `channels/<slug>/lexicon-ignore.json`, где применимо).
   - **Слой 4 — вычитка владельца в «календаре»:** финальное решение; без правок → публикация по графику.
   - Ограничения стилистики: не менять факты/смысл, CTA и ссылки (кроме осознанных корректных правок фактов), не раздувать «водой»/выдумками ради длины; объём до 4000, 3500–4000 — ориентир где уместно (см. `style.md`).
3. **Содержимое превью:** **текст + медиа как будет публиковаться, без дат**.
   - Медиа для превью — **с хостинга** (`/0s3/blogger-data/media/catden/<дата>/`), залитые в четверг.
   - Альбом (`image_files`) — все вложения; одиночное `image_file` — одно вложение; без медиа — только текст.
   - Посты `status: draft` (31.12/01.01/07.01 до готовности) — включать текстом с явной пометкой, что медиа от владельца ещё не залито / пост не `approved`.
4. **Куда отправлять:** приватный канал «календарь» (MAX). Правило 2г `AGENTS.md`: ключ `calendar` в `local/tokens.json`, `POST https://platform-api2.max.ru/messages?chat_id=...` с `{"text": ..., "format": "markdown"}` и вложениями по upload-API — **без поля `notify`**. `chat_id` только из `local/tokens.json`.
5. **Ограничения:** ≤4000 символов текста на сообщение (связку «пост + медиа» при необходимости разбивать, сохраняя порядок). Загрузка медиа — upload-API (AGENTS.md 5/8а). TLS: при необходимости `MAX_HTTP=python`, `MAX_CA_CERT=local/russian_ca_bundle.pem`.
6. **Результат вычитки:** правки есть → обновить файлы постов/медиа/статусы и синхронизировать; правок нет → ничего не менять, посты публикуются по графику.
7. **Не путать:** `docs/blogger-calendar.md` — авто-отчёт (задача 07:20), руками не правится.

**Ограничения автоматизации:** «стилистика через ИИ (агент)» выполняется при запуске агента. На 18.11.2026 отдельная headless-задача Планировщика для агента не настроена (см. прецедент na100: opencode CLI не в PATH) — для максимального автомата пятничный прогон инициируется в минимальном режиме (напр. открытая сессия/команда владельца «готовь пятничную вычитку catden» или будущая обёртка-задача), без дополнительных уточнений в процессе. Проверки слоёв 1–3 для превью в «календарь» выполняются на тексте кандидата до отправки (не путать с `publish_post.py`, который публикует в канал).

## 5. Оркестрация и отчётность (`E:\github\kalendar`)

- **Команда синхронизации:** «прочти `E:\github\kalendar` и все синхронизируй». Протокол выполнения — `E:\github\kalendar\SYNC.md`; скрипт отчёта/проверок — `py E:\github\kalendar\sync.py` (МСК-дата авто, `--force thu|fri`, `--post-status`, `--send-preview` для текстового превью после слоёв 1-3 и стилистики).
- **Служебная команда catden:** `roles/blogger/config/catden-automation.json` (долговременное состояние: `agreed_until`, параметры цикла, заметки). В `plan.json` присутствует служебная задача `orch-catden-autopilot` (`source: kalendar`, ссылка на `automation.json`); `roles/blogger/tools/export_plan.py` сохраняет задачи `source` `kalendar`/`orchestrator` и `id` с префиксом `orch-` при регенерации.
- **Четверг (по команде sync/в четверг):** медиа на хостинг, окно 11 дней вперёд — сверка/заливка/очистка по `automation.json` и манифесту/front matter; при отсутствии доступа к хостингу/оригиналам — явный отчёт с перечнем файлов/дат (без скрытых пропусков).
- **Пятница (по команде sync/в пятницу):** агентный прогон — стилистика через ИИ (агент) + слои 1-3 на тексте кандидата **до отправки**, затем превью 10 дней в «календарь» (текст+медиа как будет публиковаться, без дат, без `notify`; медиа — с хостинга). Если медиа с хостинга недоступно для вложения — текст с явной пометкой, вычитка текста не блокируется. Слой 4 — владелец в «календаре».
- **Публикация 20:00 МСК:** `publish_scheduled.py`/хостинг берёт `approved`-посты с датой из имени файла ≤ сегодня и без `message_id`. Если файла `YYYY-MM-DD-*.md` на сегодня в `posts/` нет — в 20:00 публикаций не будет (вхолостую), даже если пост этого дня уже вышел ранее другим слотом.
- **Отчётность:** MAX отдаёт план через `plan.json` и `drop.py` в хаб (`plans/MAX.json`), `PLAN.md` собирается хабом. Операционный статус с 18.11.2026: **«автопубликация готова на N дней»** (N — сколько дней вперёд готовы approved-посты с медиа на FTP; N считается от сегодняшней даты как `ready_until − сегодня`, в `state.ready_days` — снимок на момент синка; ниже порога пополнения — предупреждение в отчёте); автопубликация — **`<дата> пост вышел на автомате`**. Старая форма «посты до <дата> готовы» не используется. Граница согласования — `state.agreed_until`, обновляется после вычитки. Состояние на 18.11.2026: 19.11–20.11 согласовано, автопубликация готова на 12 дней (по 30.11).
- При изменении сетки/статусов: `py roles\blogger\tools\export_plan.py`, затем `drop`/сборка хаба по правилам `E:\github\kalendar/README.md` (с чек-листом безопасности коммитов).

## 8. Известные ограничения и что проверять на месте

- Панель Beget может быть в режиме восстановления — обходной путь: файловый менеджер/SSH/SFTP/FTP.
- FTP (наблюдалось): `mitiba.beget.tech`; аккаунт `mitiba_crossbot` → `/0s3/public_html` (не покрывает `/0s3/blogger-data/...`) — для медиа нужен доступ к `/0s3/blogger-data`.
- Sprutio — тяжёлый JS-интерфейс; для автоматизации предпочтительнее прямой файловый доступ.
- Локальные `nev/posting/images/...` в git/на машине могут отсутствовать — брать оригиналы из известного хранилища.
- Агентный пятничный прогон (стилистика + слои 1–3) требует запуска агента; полностью unattended-запуск агента не настроен — планировать минимальный триггер без лишних вопросов владельцу.
- Для превью в «календарь» «медиа с хостинга» выполнимо при доступе к хостингу; при недоступности — явно помечать в сообщении, что медиа будет подтянуто с хостинга к публикации.
- TLS/API: AGENTS.md 5 и 8а (`MAX_HTTP=python`, `MAX_CA_CERT=local/russian_ca_bundle.pem` при необходимости). Отправка в `calendar` — без `notify`.

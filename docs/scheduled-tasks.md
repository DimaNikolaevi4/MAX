# Задачи Планировщика Windows (ainow + zabava + na100)

Настроены 09.11.2026, расписание упрощено 10.11.2026: один слот сбора данных и
один слот публикации. 11.11.2026 задачи были обнаружены отсутствующими
(в системе остались только задачи AMD, Яндекс.Браузера и Office) —
перерегистрированы скриптом `roles/blogger/bin/register_tasks.ps1`, см.
раздел «Регистрация задач». Работают под текущим пользователем, только когда
он в системе (LogonType Interactive): ПК выключен или пользователь не вошёл —
запуск пропускается, при следующем входе сработает `StartWhenAvailable`.

| Задача | Когда (МСК) | Что делает |
|---|---|---|
| `MAX stats snapshot` | ежедневно 07:00 | снимает подписчиков и просмотры для ainow и zabava, отчёт за предыдущие сутки |
| `MAX ainow - publish approved` | ежедневно 07:15 | публикует все посты со `status: approved`, дата из имени файла ≤ сегодня |
| `MAX zabava - publish plan` | ежедневно 07:16 | публикует все `pending` посты из `local/zabava-plan.json` |
| `MAX blogger calendar` | ежедневно 07:20 | пересобирает `docs/blogger-calendar.md` (публикации, план, удаления) и пушит его |
| `MAX na100 - publish approved` | ежедневно 07:30 | публикует `approved`-выпуск дайджеста na100 (обёртка `publish_scheduled_na100.ps1`) |

Ограничений по количеству публикаций в день или неделю и по интервалу между
постами нет: в 07:15 (ainow) и 07:16 (zabava) выходит всё, что готово. Zabava
сдвинута на минуту позже ainow, чтобы два git-push не сталкивались в одну
секунду.

**«Только утром».** У задач включён `StartWhenAvailable`: если ПК был выключен
в слот запуска, задание догонит при следующем включении — хоть днём, хоть
вечером. Чтобы такой «догон» не публиковал посты вне утра, в обёртках
(`roles/blogger/bin/*.ps1`) стоит проверка утреннего окна **07:00–10:00**:
запуск вне окна ничего не делает и пишет в лог строку «вне утреннего окна».
(Кейс 10.11.2026: сдвинутый на 07:16 триггер планировщик счёл пропущенным
стартом и догнал при включении ПК в 16:33 — пост вышел в 16:38. После правки
такой запуск пропустился бы.)

## Календарь блогера (07:20)

Задача `MAX blogger calendar` запускает `roles/blogger/bin/calendar_update.ps1` →
`roles/blogger/tools/build_calendar.py --push`. Скрипт каждый день заново
собирает `docs/blogger-calendar.md`:

- **сводка** — сколько вышло за 30 дней по каналам, сколько ждёт публикации;
- **каналы** — площадка, состояние (`под удаление` + дата удаления из реестра);
- **сегодня** — что вышло сегодня (время, ссылка) и следующий пост из плана;
- **запланировано** — посты `approved` по дате и `pending` из плана «Забавного»;
- **публикации за 30 дней** — дата, просмотры, ссылка;
- **удалено** — посты со `status: deleted`/`deleted_at` и удаления каналов целиком;
- **черновики**.

Данные берутся из front matter постов, `local/zabava-plan.json` и
`roles/blogger/config/channels.json` — отдельного хранилища нет, календарь
всегда пересобирается с нуля. Ручные правки файла бессмысленны: следующий
запуск перезапишет. Лог — `local/logs/calendar.console.log`.

Удаление поста фиксируется автоматически: `delete_post_by_slug.py` после
успешного `DELETE` ставит в файл поста `status: deleted` и `deleted_at`, коммитит
и пушит его — на следующем запуске пост попадёт в раздел «Удалено».
Удаления до 10.11.2026 в постах не отмечались, поэтому в календаре их нет.

## Публикация: как это устроено

1. Владелец говорит «ок» в рабочем чате.
2. Агент переводит пост из `status: draft` в `status: approved`.
3. В 07:15 задача запускает
   `roles/blogger/tools/publish_scheduled.py`:
   - `git fetch`; если `origin/main` ушёл вперёд — публикация откладывается;
   - проверяет картинку, CTA-цитату и уникальность фразы призыва;
   - публикует через `publish_post.py` (upload, POST, GET-контроль);
   - дописывает CTA-фразу в `cta-phrases.json`;
   - коммитит пост и реестр, делает `git push origin main`;
   - пишет отчёт в `local/scheduled-publish.txt`, лог — `local/logs/`.
4. `draft` без «ок» не публикуется никогда; `published` повторно не берётся.
5. Запуск публикует **все** готовые посты (`--limit 0`), защита от
   параллельных запусков — `local/publish-scheduled.lock`.

Ручной запуск и проверка:

```powershell
cd E:\github\MAX
py roles\blogger\tools\publish_scheduled.py --channel ainow --dry-run
py roles\blogger\tools\publish_scheduled.py --channel ainow
```

## Статистика: что снимается

`roles/blogger/tools/stats_snapshot.py` через MAX Bot API берёт:

- `GET /chats/{chat_id}` — подписчики, число сообщений;
- `GET /messages?chat_id=...&count=100` — просмотры каждого поста (`stat.views`).

Пишет по каждому каналу:

- `local/stats/ainow-YYYY-MM-DD.json`, `local/stats/zabava-YYYY-MM-DD.json` —
  снимок дня (один файл на день);
- `local/stats-report-ainow.txt`, `local/stats-report-zabava.txt` — период
  (предыдущие сутки), прирост подписчиков, новые посты, топ прироста просмотров;
- `local/logs/stats.log` — история запусков.

Задача `MAX stats snapshot` запускает `roles/blogger/bin/stats_snapshot.ps1`,
который последовательно снимает оба канала.

Снимок снимается утром в 07:00, поэтому отчёт покрывает **предыдущие сутки**:
от вчерашнего снимка (07:00) до сегодняшнего. В отчёте это указано строкой
`период: ... → ... (сутки)`. Просмотры в отчёте — прирост за период, а не
накопленные значения.

Порядок в 07:00 важен: снимок идёт **в 07:00**, публикация — **в 07:15/07:16**.
Поэтому утренний снимок фиксирует состояние до выхода нового поста, а сам
пост попадает в следующий отчёт уже с просмотрами за полные сутки, а не с
нулём.

Недельная сводка (по каждому каналу отдельно):

```powershell
py roles\blogger\tools\stats_snapshot.py --channel ainow --weekly
py roles\blogger\tools\stats_snapshot.py --channel zabava --weekly
```

Ограничения API: нет реакций, охвата, CTR по ссылкам, источников трафика и
истории подписчиков — только просмотры и текущее число участников.
`count=100` — последние 100 сообщений; для канала этого достаточно.

## «Забавное» (zabava): публикация по плану

- Задача `MAX zabava - publish plan` — ежедневно в **07:16** (на минуту позже
  ainow, чтобы git-push каналов не сталкивались).
- Запускает `roles/blogger/tools/publish_plan.py`: берёт первый `pending` пост
  из `local/zabava-plan.json` и публикует его. Никаких проверок интервала и
  дневного лимита нет; обёртка повторяет запуск, пока в плане остаются
  `pending` — то есть за один слот уходит всё, что подготовлено.
- Отчёты: `local/publish-plan.txt`, лог — `local/logs/zabava-publish.console.log`.
- Публикует через `publish_video.py`: проверка текста, загрузка медиа, POST,
  GET-контроль, обновление front matter, CTA-фраза дописывается в
  `roles/blogger/channels/zabava/cta-phrases.json`.
- После успеха исходный пост-донор (`source`) удаляется, если в записи плана не
  указано `delete_source: false`.
- Если публикатор вернул ошибку контроля, но пост уже ушёл (front matter
  `status: published`), план всё равно помечается `published` — повторной
  публикации не будет.
- После публикации пост коммитится и пушится автоматически
  (`roles/zabava: publish ... (plan)`); медиа-файлы в git не попадают — они
  лежат в `local/` (gitignore), а в `.md` остаётся ссылка на CDN
  (`https://i.oneme.ru/i?r=...&expires=...`, со временем ссылка умирает,
  локальная копия остаётся).

Добавить пост: положить `.md` в `roles/blogger/channels/zabava/posts/`, медиа —
в `local/images/zabava/`, дописать запись в `local/zabava-plan.json` со
`status: pending`. Остановить автопубликацию —
`Disable-ScheduledTask -TaskName 'MAX zabava - publish plan'`.

## na100 («Новости мира техники»): публикация выпуска

- Задача `MAX na100 - publish approved` — ежедневно в **07:30**, обёртка
  `roles/blogger/bin/publish_scheduled_na100.ps1` →
  `roles/blogger/tools/publish_scheduled.py --channel na100`. Публикует все
  посты канала со `status: approved`, у которых дата из имени файла ≤ сегодня;
  `published` повторно не берётся. Отчёт — `local/publish-na100.txt`, лог —
  `local/logs/publish-na100.console.log`.
- **Утреннее окно 07:00–10:00** — то же правило, что у остальных задач: догнавший
  запуск вне окна ничего не публикует.
- **Обложка обязательна до публикации.** У поста должен быть существующий
  `image_file` (обычно `local/digest/cover-*.png`, собирается
  `digest_cover_photo.py` на фоне из пула, см.
  `roles/blogger/channels/na100/cover-method.md`). Если файла нет — публикатор
  падает с `FAIL: нет медиа` и выпуск не выходит; проверить заранее можно
  `py roles\blogger\tools\publish_scheduled.py --channel na100 --dry-run`.
- **Подача по методике 11.11.2026:** только нумерация 1️⃣–5️⃣, без гео-надписей
  («Россия:/Китай:/Мир:») и без эмодзи-флагов/глобуса; порядок новостей
  перемешивается перед выпуском, состав (1 РФ + 1 Китай + 3 мира) не меняется.
  Пункты панели обложки идут в том же порядке, что нумерация в посте.
- **Обложка: авто-тема может ошибаться.** На пёстром фоне `--theme auto`
  однажды выбрал светлую тему (тёмно-синий текст) при тёмных серверных
  стойках в зоне мачхеда — текст стал нечитаемым. Если фон контрастно-пятнистый,
  ставить `--theme dark|light` вручную и проверять результат глазами.
- **Закреплять посты na100 нельзя** без прямой команды владельца (правило
  11.11.2026). После чистки канала закрепа нет.
- **Название и описание канала зафиксированы текущими** (решение 11.11.2026):
  «Новости технологий ИИ, нейросетей и инноваций» и описание про новости
  технологий/ИИ/инноваций. Переименование в «Новости мира техники» и новое
  описание в MAX не применяются — `channels.json` остаётся источником для
  текстов, но сам канал не переименовывается.

## Регистрация задач

Задачи ставятся одним скриптом (идемпотентно, с `-Force`):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File roles\blogger\bin\register_tasks.ps1
```

Скрипт создаёт все пять задач с `LogonType Interactive`, `RunLevel Limited`,
`StartWhenAvailable` и границами старта ровно в 07:00 / 07:15 / 07:16 / 07:20 / 07:30
без случайной задержки.

**Ловушки:**

- `.ps1` с кириллицей сохранять **в UTF-8 с BOM** (`utf-8-sig`). Без BOM
  PowerShell 5.1 читает файл как ANSI: логи пишутся кракозябрами
  (`РІРЅРµ СѓС‚СЂРµРЅРЅРµРіРѕ…` вместо «вне утреннего…»), а строки с
  кириллицей могут валить парсер. Так было у `publish_scheduled_na100.ps1` —
  исправлено 11.11.2026.
- `Get-ScheduledTaskInfo` показывает `NextRunTime` со «лишними» секундами
  (7:15:15) — это косметика отображения; реальная граница (`Triggers.StartBoundary`)
  ровная.

## Telegram (tg_neuro): черновики заблокированы

Три черновика (`2026-11-02-vtoraya-chast-chto-dalshe`,
`2026-11-03-otvety-na-voprosy`, `2026-11-10-zveri-i-ulybki`) готовы к тексту,
но опубликовать их сейчас нельзя — проверено 11.11.2026:

- релей `https://0s3.ru/tg-relay/tg-relay.php` отдаёт код `000` (хостинг
  недоступен, как и 02–04.11.2026);
- резервный путь `tg_direct.py --ip 149.154.167.220` — `Test-NetConnection`
  на `149.154.167.220:443` = `False`, IP закрыт;
- в `local/tokens.json` нет записи `tg_neuro` (`relay_url`, `secret`, `token`,
  `chat_id`) — без неё не работает ни релей, ни прямой путь.

Чтобы выпустить: вернуть хостинг/релей и заполнить `local/tokens.json`:
`"tg_neuro": {"relay_url": "https://<домен>/tg-relay/tg-relay.php",
"secret": "...", "chat_id": "-1002087111322"}` (или `token` для прямого пути).

## Управление задачами

```powershell
Get-ScheduledTask -TaskName 'MAX*' | Select-Object TaskName,State
Get-ScheduledTaskInfo -TaskName 'MAX stats snapshot'
Start-ScheduledTask -TaskName 'MAX stats snapshot'   # прогнать сейчас
Disable-ScheduledTask -TaskName 'MAX ainow - publish approved'
Enable-ScheduledTask  -TaskName 'MAX ainow - publish approved'
Unregister-ScheduledTask -TaskName 'MAX ainow - publish approved' -Confirm:$false
```

Отчёты после автоматических запусков в чат не приходят: публикация —
`local/scheduled-publish.txt`, статистика — `local/stats-report-<канал>.txt`,
план «Забавного» — `local/publish-plan.txt`, календарь — `docs/blogger-calendar.md`
(или запросить у агента в следующей сессии).

# Расписание публикаций (только хостинг)

> Состояние на 22.11.2026. Локальные задачи Планировщика Windows **полностью
> упразднены**: на машине их больше нет, в репозитории упоминаний и обёрток нет.
> Автоматическая публикация идёт **только через хостинг-крон**. Всё остальное —
> личная правка владельца или действие агента по его прямой просьбе.

Этот файл — единственный источник конкретных времён слотов. `publish_window`
в `roles/blogger/config/channels.json` — только окно догона
(`[start_hour,end_hour]` или `null`), **не** времена публикации.

## Единая таблица слотов

| Канал / задача | Время (МСК) | Где | Примечание |
| --- | --- | --- | --- |
| ainow | 12:00 | хостинг, `post_cron.php` | кросс-пост Format 1, `publish_time` в посте |
| ainow | 21:30 | хостинг, `post_cron.php` | посты плана |
| catden | 20:00 | хостинг, `post_cron.php` | единый слот; утренний 07:32 отменён |
| zabava | 19:30 | хостинг, `post_cron.php` | обычно 1 пост/сутки (D3); второй пост допустим |
| administrator | вт/чт 09:00 | хостинг, `post_cron.php` | через `publish_time` в посте |
| Статистика | 07:45 | хостинг, `stats_cron.php` | 4 канала: ainow, na100, zabava, catden |

**Format 1** — кросс-пост `ainow` в 12:00 МСК: пост `ainow` с полем
`publish_time` во front matter, который хостинг публикует в дневной слот вместо
слота плана `21:30`. Это не особый формат текста: пост подчиняется
`AGENTS.md §0`; термин описывает только время и способ публикации.

## na100 — утренний выпуск

- Локального таймера и хостинг-автопоста для na100 **нет** (не добавлять в
  `post_cron.php`).
- Утром владелец даёт агенту команду; агент собирает дайджест из
  `roles/blogger/channels/na100/digests/<дата>-draft.json`, проверяет по
  `AGENTS.md §5а` и **`format_core`** (`check_post.py --channel na100`), затем
  публикует approved-пост **прямо в канал**.
- Целевой ориентир времени — 07:30 МСК, но это не автоматический слот:
  выпуск выходит, когда владелец дал команду и пост готов.

## Календарь блогера

`docs/blogger-calendar.md` обновляется агентом по просьбе владельца:
`py roles/blogger/tools/build_calendar.py --push`. Никаких фоновых задач нет.

## Хостинг-скрипты

Рабочие копии лежат в `deploy/`: `post_cron.php`, `stats_cron.php`,
`tg-relay.php` (подробности — `deploy/README.md`). Скрипты читают посты из
`main`, состояние — из `/0s3/blogger-data/state/`, токены — с хостинга вне
webroot. Web-обёртка `post_web.php?s=<secret>` работает в DRY без `go=1`;
реальный запуск — `go=1` либо вызов из cron.

Правила формата в PHP-кропе — подмножество `shared/format_core.py`; при
расхождении источник истины — `AGENTS.md §0`.

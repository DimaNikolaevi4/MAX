# Вход для нового ИИ-агента

Короткий вход: что читать, что проверить, чего не делать. Полная методика —
`AGENTS.md`; главный источник формата — `AGENTS.md` §0 FORMAT CORE v1.
При расхождении документов приоритет: §0 → AGENTS.md → `style.md` канала →
`docs/` → `README` (обзор, не норма).

## 1. Порядок чтения

1. `AGENTS.md` §0 — FORMAT CORE v1, матрица, legacy-оговорка.
2. `AGENTS.md` целиком — жизненный цикл, безопасности, API.
3. `roles/blogger/config/channels.json` — slug, `format_profile`, `cta_target_mode`,
   `cta_label`, `cta_url`, лимиты канала.
4. `roles/blogger/channels/<slug>/style.md` — дельты канала. Для `zabava` и
   `tg_neuro` этот файл канонический и §0 не применяется.
5. `roles/blogger/channels/<slug>/cta-phrases.json`, reaction registry — фразы
   призыва и учёт реакций.
6. `docs/agent-onboarding.md` — этот файл; `docs/bot-setup.md` — только при
   подключении нового канала.

## 2. Проверить перед работой

- `local/tokens.json` существует и содержит запись канала (`token`, `chat_id`),
  файл gitignored; токены никуда не копировать.
- Связь: `curl.exe --cacert local/russian_ca_bundle.pem -H "Authorization: <токен>"
  https://platform-api2.max.ru/me` → HTTP 200. При TLS-ошибке — `MAX_HTTP=python`
  и `MAX_CA_CERT=local/russian_ca_bundle.pem`.
- `py shared/verify_layout.py` — 0 ошибок, 0 предупреждений.

## 3. Железные правила

- Токены только в `local/tokens.json`; не в git, не в постах, не в логах.
- Формат ядра: только для постов с `format_core: 1`. Новым постам ядра поле
  ставится при создании; существующие посты без поля — legacy, не переписываются.
- Порядок ядра: CTA-цитата — предпоследний блок, пустая строка, вопрос со `?`
  последним блоком. Реакции — между ними, ≤ 1 строки, по реестру.
- Длина ≤ 4000; жирных в абзацах ≤ 6; без markdown-списков, таблиц, `###`,
  backtick; блоки кода/промптов — цитатой разрешены.
- CTA: `self` у ainow/catden, чередование `self ↔ ainow` у na100/administrator
  через `cta_target`. Без поля — `self` + предупреждение владельцу.
- Перед PUT: GET текущего состояния, правки с контролем вхождений, после —
  GET-контроль вложений и разметки.
- Каждый значимый шаг — коммит; `git add` только поимённо; строк `D` без
  намерения быть не должно.

## 4. Среда и API

- Windows, PowerShell 5.1; `py`, не `python`. Консоль cp1251: кириллицу и эмодзи
  в консоль не печатать, писать в файл и читать инструментом чтения.
- TLS: `platform-api2.max.ru` и CDN `iu.oneme.ru` требуют разных контекстов;
  рабочая схема — `MAX_HTTP=python` + `MAX_CA_CERT`.
- Позиции разметки в API — UTF-16; эмодзи вне BMP занимают 2 единицы.
- MAX не рендерит markdown-списки и таблицы; цитата `>` в GET-разметке не
  возвращается, но работает при отправке.

## 5. Жизненный цикл

- **Новый пост**: черновик (`status: draft`) → чек-лист → показать текст человеку
  → «ок» → `approved` → публикация по расписанию или вручную по команде →
  GET-контроль → архив → коммит.
- **Отложенная публикация**: разрешена планом и хостинговым cron; в API её нет.
  Время задаётся `publish_time` во front matter; дата — именем файла.
- **Правка опубликованного**: по прямой команде; PUT без вложений (они
  сохраняются), `edited_at`, аудит в отчёте.
- **Черновики и digests**: лежат в git (`roles/blogger/channels/*/posts/`,
  `roles/blogger/channels/na100/digests/`). В `local/` — только токены, логи,
  медиа, временные отчёты.

## 6. Чего не делать

- Не публиковать без изображения/видео и CTA; не генерировать картинки без
  прямого указания, кроме разрешённых §5б заставок na100 и карточки administrator.
- Не повторять фразы CTA и не нарушать интервал реакций.
- Не править посты `approved_by_owner: true` без прямой команды.
- Не трогать посты других каналов, не работать в личке бота AI Now,
  не выполнять задачи соседних репозиториев без отдельной команды.

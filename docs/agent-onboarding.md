# Вход для нового ИИ-агента

Вы — ИИ-агент, подключённый к этому репозиторию, чтобы готовить и публиковать
посты в каналы мессенджера MAX. Этот документ — короткий вход: что читать, что
проверить, чего не делать. Полная методика — `AGENTS.md` (прочитайте целиком).

## 1. Порядок чтения (обязательно, до первого действия)

1. `AGENTS.md` — операционная методика: жизненный цикл поста, лимиты, проверки.
2. `config/channels.json` — реестр каналов (slug, `cta_label`, `cta_url`).
3. `channels/<slug>/style.md` — стиль вашего канала (формат поста, тон, запреты).
4. `channels/<slug>/cta-phrases.json` — использованные фразы призыва: не
   повторять их в новых постах.
5. `channels/<slug>/proofread.md` — статус вычитки и история правок (если есть).
6. `docs/bot-setup.md` — только если подключаете НОВЫЙ канал или бота.

## 2. Проверить перед началом работы

- `local/tokens.json` существует и содержит запись вашего канала
  (`token`, `chat_id`) — файл gitignored, в свежем клоне его нет: создайте по
  шаблону `local/tokens.example.json`, токен возьмите у человека.
- Проверка связи: `curl.exe -H "Authorization: <токен>" https://platform-api2.max.ru/me`
  → HTTP 200 и `is_bot: true`.

## 3. Железные правила (нарушать нельзя)

- **Токены только в `local/tokens.json`** — никогда в git, в постах, в логах.
- **Лимиты API**: не более 2 сообщений/сек на канал (публикация и правки —
  общий лимит; держите паузу ≥0.6 с между вызовами), текст ≤ 4000 символов.
- **Формат поста** (`channels/<slug>/style.md`): изображение вложением,
  заголовок жирным, воздух `\n\n` между блоками, нижний блок — цитата-призыв
  `> **Подписывайтесь на [<метка>](<url канала>)** — <своя фраза>`.
- **Перед каждым PUT — dry-run/проверка**: сначала GET текущего состояния,
  замены с проверкой вхождений (ровно 1), после PUT — GET-контроль
  (вложение цело, разметка на месте, `>` не попал в текст).
- **Одноразовые файлы задания** (`local/fix-*.json`) после применения удалять —
  иначе повторный прогон упадёт (вхождений 0).
- **Каждый значимый шаг — коммит и пуш.**

## 4. Особенности среды и API (проверено на практике)

- Windows: консоль в cp1251 — Unicode в консоль не печатать, писать в файл
  и читать инструментом чтения файлов; inline-python с кавычками в PowerShell
  ломается — скрипты сохранять в файлы.
- TLS: в изолированных средах python-requests падает по сертификатам —
  использовать системный `curl.exe`.
- Позиции разметки в API — в UTF-16 кодовых единицах (эмодзи вне BMP = 2
  единицы; пересчёт префикс-суммами, образец — `tools/ensure_cta_quote.py`).
- MAX НЕ рендерит markdown-списки (`- `, `1. `) и таблицы (`| |`) — маркеры
  писать литерально («— », «• », 1️⃣), таблицы заменять списком пар.
- Цитата `>` работает при отправке, но GET её в markup не возвращает —
  признак успеха: `>` исчез из текста, инлайн-разметка внутри цела.
- Загрузка изображения: `POST /uploads?type=image` → одноразовый url →
  `curl -F "data=@file"` → токен из `{"photos":{"0":{"token":...}}}` →
  `attachments: [{"type":"image","payload":{"token":...}}]`.

## 5. Жизненный цикл (кратко; полностью — `AGENTS.md`, раздел 3)

- **Новый пост**: черновик → чек-лист 5а → показать текст целиком в рабочем
  чате → «ок»/правки там → публикация → GET-проверка → архив → уведомление
  в личку бота → коммит. Отложенные публикации не делать.
- **Правка опубликованного**: автопилот без ожидания — правка → PUT →
  GET-проверка → архив → уведомление в личку → коммит. При любой правке
  проверять CTA-блок.

## 6. Чего не делать

- Не публиковать пост без изображения и без CTA-цитаты.
- Не повторять фразы призыва между постами.
- Не трогать посты и файлы чужих каналов.
- Не ждать «ок» в личке MAX — там только уведомления; согласование новых
  постов — в рабочем чате с человеком.
- Не хранить черновики и одноразовые скрипты в git — рабочее место `local/`.

# Методология техно-дайджеста na100 — изображения

> Зафиксировано 11.11.2026. Правила канала — `roles/blogger/channels/na100/style.md`
> (раздел «Картинки — политика заимствования v2»); этот документ — рабочая
> логика модуля сборки: дерево решений, тайм-бюджеты, атрибуция, учёт.
> Методика заставок (генерация и грабли) — `roles/blogger/channels/na100/cover-method.md`.

## 1. Задача, которую решает модуль

Один пост = **одна обложка** (одно изображение на выпуск), а не по картинке
на каждую новость. Обложка должна:

- быть релевантной **одному из сюжетов выпуска** (не обязательно главному);
- не нарушать авторские права;
- иметь проверяемую атрибуцию;
- выглядеть частью стиля канала, а не «случайным фото из интернета».

## 2. Принципы (в порядке приоритета)

1. **Право важнее наличия.** Лучше заставка, чем фото с неясной лицензией.
2. **Релевантность важнее наличия.** Фото «ради галочки» не тянем — если нет
   тематически подходящего снимка, сразу заставка.
3. **Кандидат из RSS ≠ разрешение.** RSS отдаёт `<enclosure>`, `media:content`,
   `media:thumbnail`, первый `<img>` в HTML — это только кандидаты.
   Использование возможно только если домен в `allowed`.
4. **Этика стоков.** Сюжеты о конкретных людях (скандалы, обвинения) не
   иллюстрируются стоковыми портретами — только нейтральные предметные кадры
   из Commons или заставка.
5. **Учёт обязателен.** По каждому взятому изображению — запись в
   `local/digest/<дата>/image-meta.json` (формат — раздел 7).

## 3. Источники по приоритету

| # | Источник | Что даёт | Условие использования | Подпись |
|---|---|---|---|---|
| 1 | **Wikimedia Commons** (API, `extmetadata`) | Документальный кадр по теме | Только CC0 / CC BY / CC BY-SA; автор и лицензия из метаданных | «Фото: Wikimedia Commons / <автор> (<лицензия>)» |
| 2 | **Unsplash / Pexels / Pixabay** (API) | Тематическая иллюстрация | Свободные лицензии банка; проверка, что сюжет не про конкретного человека | «Иллюстрация: <банк> / <автор>» |
| 3 | **RSS из `allowed`-домена** | Кандидат из статьи | Домен в `allowed` (добавлен вручную после явного разрешения, копия правил сохранена); фильтры размера и URL-паттернов | По `credit_type` домена — раздел 6 |
| 4 | **`digest_cover.py`** (заставка) | Брендированный шаблон | Всегда доступен | Без подписи (наш шаблон) |

Дополнительно: `digest_cover_photo.py` / `digest_cover_video.py` — наложение
брендированной плашки поверх найденного фото/видео-фона.

**Что не используется никогда:** агентства и стоки без лицензии (Reuters, AP,
Getty, Shutterstock и т.п.) — в `denied` конфига. RSS-теги `copyright` /
`creativeCommons:license` — слабый сигнал, сами по себе основанием не
считаются (`weak_signals_deny_by_default`).

## 4. Дерево решений

Сюжет-кандидат — **любая из новостей выпуска** (не только главная): выбирается
лучшая пара «сюжет × фото» — релевантность снимка × вес новости. Фото «ради
галочки» к слабому сюжету не тянем. Подпись в посте всегда привязывает фото к
конкретному сюжету.

**Шаг 1. Есть ли тематически подходящий кадр в Commons?**
- Ищем по ключевым сущностям новостей (компания, продукт, событие).
- Найден и лицензия CC0 / CC BY / CC BY-SA → берём, «Фото: Wikimedia
  Commons / …». Нет → шаг 2.

**Шаг 2. Есть ли нейтральная иллюстрация в фотобанках?**
- Ищем по теме («microchip», «electric vehicle», «data center»).
- **Проверка этики:** сюжет про конкретного человека или скандал → сток не
  берём, сразу шаг 4.
- Найдена → берём, «Иллюстрация: <банк> / <автор>». Нет → шаг 3.

**Шаг 3. Есть ли кандидат в RSS из `allowed`-домена?**
- Домен статьи в `allowed`? Нет → шаг 4 (мгновенно, без запросов).
- Извлекаем картинку: `<enclosure>` → `media:content` → `media:thumbnail` →
  первый `<img>` в HTML.
- Фильтры: ширина > 600 px; URL без `logo`, `avatar`, `icon`, `banner`,
  `sprite`; формат jpg / png / webp.
- Прошла → берём, подпись по `credit_type` домена. Нет → шаг 4.

**Шаг 4. Заставка.**
- `digest_cover.py`: шаблон + дата + короткие заголовки тем выпуска.
- Это **штатный** fallback, а не «аварийный» — она должна выглядеть частью
  стиля, а не «дырой».

## 5. Тайм-бюджет (без «поиска ради поиска»)

| Этап | Бюджет | Правило остановки |
|---|---|---|
| Commons | ≤ 90 сек | 2–3 варианта запроса, не больше |
| Фотобанки | ≤ 60 сек | 1 запрос по теме, без перебора синонимов |
| RSS allowed | ≤ 30 сек | домен не в allowed → шаг пропускается мгновенно |
| **Итого на выпуск** | **≤ 3 мин** | не нашли → заставка, без «продолжить поиск» |

«Не нашли» — нормальный исход, а не задержка пайплайна: сборка должна
уложиться в окно 06:30 → публикация 07:30.

## 6. Атрибуция: таблица тип → подпись

| Тип изображения | Подпись в посте |
|---|---|
| Commons, документальный кадр | «Фото: Wikimedia Commons / <автор> (<лицензия>)» |
| Фотобанк, иллюстрация | «Иллюстрация: <банк> / <автор>» |
| RSS из allowed, `credit_type: "documentary"` (пресс-центр, официальный рендер/хендаут) | «Фото: пресс-служба <компании>» |
| RSS из allowed, `credit_type: "illustration"` | «Иллюстрация: <домен>» |
| Заставка `digest_cover.py` | без подписи (наш шаблон) |

Атрибуция обязательна даже для CC0 (там достаточно «Wikimedia Commons») —
это не только юридическое требование, но и сигнал доверия читателю.

### credit_type (решение по RSS из allowed)

**По умолчанию — «Иллюстрация», пока для домена явно не зафиксирован
`credit_type: "documentary"`.** Поле живёт в `config/image_sources.json`,
ставится один раз на домен (не на каждую картинку):

- `documentary` — только если одновременно:
  1. на странице правил домена есть явное разрешение на перепечатку с
     атрибуцией (копия правил сохранена в `local/digest/`);
  2. изображение в статье привязано к событию/продукту, о котором новость
     (официальный рендер, пресс-фото анонса, хендаут), а не декоративная
     подложка.
- `illustration` — во всех остальных случаях: домен в allowed, но тип
  изображения не гарантирован, или это generic-подложка сайта.

Почему так: «Фото:» — утверждение, что снимок документирует событие; ошибка
здесь — репутационный и юридический риск. «Иллюстрация:» — честная маркировка
без ложных ожиданий. `allowed` пополняется вручную, поэтому решение
принимается в момент добавления домена — дёшево и воспроизводимо.

Практическое следствие: стартовый `allowed: []` — штатное состояние. Первые
домены появятся после проверки условий пресс-центров (Apple Newsroom, Google
Blog, Microsoft News, Samsung Newsroom, NVIDIA Newsroom) и сохранения копий
правил. До этого модуль работает на цепочке Commons → фотобанки → заставка.

## 7. Метаданные (`image-meta.json`)

По каждому взятому изображению — запись в `local/digest/<дата>/image-meta.json`:

```json
{
  "date": "2026-11-11",
  "type": "documentary | illustration | cover",
  "source": "wikimedia | unsplash | rss | cover",
  "domain": "commons.wikimedia.org",
  "author": "Имя Фамилия",
  "license": "CC BY-SA 4.0",
  "url": "https://...",
  "credit_line": "Фото: Wikimedia Commons / Иван Иванов (CC BY-SA 4.0)",
  "relevance_check": "product_render | event_photo | neutral_topic | fallback"
}
```

Даёт аудит: через месяц видно, сколько было документальных кадров,
иллюстраций и заставок — и калибруется цепочка.

## 8. Итоговая цепочка (кратко)

```
для каждого сюжета выпуска (быстро, по тайм-бюджету):
  Commons (CC0/CC BY/CC BY-SA)
    → фотобанки (Unsplash/Pexels/Pixabay, с этической проверкой)
      → RSS только из allowed (подпись по credit_type)
выбрать лучшую пару «сюжет × фото» → иначе заставка digest_cover.py
```

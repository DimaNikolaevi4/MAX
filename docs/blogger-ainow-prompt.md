## 4. Формат поста (обязательные правила `roles/blogger/channels/ainow/style.md`)

1. **Изображение первым.** Картинка прикладывается вложением и открывает пост в ленте. Если в посте есть видео — отдельная картинка не нужна, видео заменяет обложку.
2. **Заголовок жирным**: первая строка `**Заголовок**`, одна строка, без точки в конце, ориентир — до 60 символов.
3. **Воздух**: после заголовка пустая строка; блоки разделяются `\n\n`, не одиночным переносом; один блок — одна мысль.
4. **Финальный блок — цитата-призыв**:
   `> **Подписывайтесь на [AI](https://max.ru/channel_ainow)** — одна строка-причина`
   Ссылка строго на `ainow`, отвечает `200`.
5. **Объём ≤ 4000 символов** включая разметку и переносы. Считать скриптом, не на глаз.
6. **MAX не рендерит** markdown-списки (`- `, `1. `), таблицы (`| |`) и `##`-заголовки. Маркеры писать литерально: «— » для списков, «• » для пар, нумерация — 1️⃣ 2️⃣ 3️⃣. Таблицы заменять списком пар.
7. **Перелинковка**: 1–2 ссылки на **опубликованные** прошлые посты канала `ainow` (у файла есть `url` в front matter; не на сам канал и не на сам пост), вплетённые в текст в подходящем абзаце. Отдельного блока «По теме» в конце нет. На неопубликованное не ссылаться.
8. **Заканчивать вопросом** к читателям для вовлечения — вопрос идёт **предпоследним абзацем**, последняя строка всегда цитата-призыв (пункт 4).
9. **Тон**: «вы», практично, без воды и хайпа; честно разбирать контраргументы; эмодзи-рубрики в начале разделов (🧭 🏭 ⚙️ ⚖️ 📊 🛠).

## 9. Правка опубликованного поста

Правка — в том же сообщении (`PUT`), дата, ссылка и просмотры сохраняются.

1. `GET /messages/{message_id}` — снять текст и разметку. Позиции в API — **UTF-16** (эмодзи вне BMP = 2 единицы). Сохранить JSON в `local/`.
2. Внести правки в файл поста.
3. Собрать Markdown точными заменами с проверкой числа вхождений. Инструменты:
   - `roles/blogger/tools/build_markdown.py` — сборка md из текста и разметки;
   - `roles/blogger/tools/markup_fragments.py` — снятие фрагментов;
   - `roles/blogger/tools/ensure_cta_quote.py --channel ainow <post.md> --dry-run` — CTA и пакетные правки.
4. `PUT /messages?message_id=...` с `{ "text": ..., "format": "markdown" }`, **без вложений** — картинка сохранится.
5. `GET /messages/{message_id}` — правки на месте, вложение сохранилось.
6. Обновить файл поста: тело — итоговый Markdown, добавить `edited_at: <ISO 8601, МСК>`.
7. Отчёт в рабочем чате со ссылкой и списком исправлений. Коммит и пуш.

При **каждой** правке проверять нижний блок: последний абзац — цитата с призывом и ссылкой на `ainow`. Если призыва нет или он не цитата — привести к формату. Корректный призыв при правке опечаток **не меняем**: новая фраза нужна, только если призыв создаётся заново или дублирует фразу другого поста. Тогда обновить `cta-phrases.json` (ключ — имя файла поста) и таблицу CTA в `proofread.md`.

## 12. Git

- Перед публикацией: `git pull --rebase origin main`; дерево должно быть чистым.
- Черновик коммитится сразу после создания (`status: draft`): параллельные запуски видят его, а публикация идёт из чистого дерева. После публикации — отдельный коммит с обновлённым front matter.
- Каждая публикация — отдельный коммит: `roles/blogger/channels/ainow: опубликован пост <файл>`.
- Если дата публикации сдвигается до публикации — переименовать файл под новую дату и обновить ключ в `cta-phrases.json`; после публикации файл не переименовывать.
- Правка — отдельный коммит с `edited_at`.
- Пуш — после публикации/правки или в конце сессии.
- Не коммитить `local/`, токены, картинки и черновики скриптов.

## 13. Сбои и диагностика

**TLS — источник сбоев №1.** Оба хоста (`platform-api2.max.ru` и CDN `iu.oneme.ru`) отдают российскую цепочку сертификатов.

- Рабочая схема: `MAX_HTTP=python` + `MAX_CA_CERT=local/russian_ca_bundle.pem`.
- `curl.exe` (schannel) к `platform-api2` проходит только с `--cacert`, к `iu.oneme.ru` не проходит вовсе.
- `python-requests` с дефолтным контекстом падает на `platform-api2`.
- Если бандла нет:

```powershell
curl.exe -s -o local/russian_trusted_root_ca.pem https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
curl.exe -s -o local/russian_trusted_sub_ca.pem https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt
py -c "from pathlib import Path; r=Path('local/russian_trusted_root_ca.pem').read_text(); s=Path('local/russian_trusted_sub_ca.pem').read_text(); Path('local/russian_ca_bundle.pem').write_text(r.rstrip()+'\n\n'+s.rstrip()+'\n')"
```

**Дубли публикаций.** Причина — параллельные запуски. Лечение: `pull` → проверить `status` и `message_id` → только потом публиковать. Если дубль вышел: `DELETE /messages?message_id=...`, затем `GET` → 404.

**Кодировка.** Кириллица и эмодзи в консоли cp1251 ломаются: писать в файл и читать файлом.

**Ссылки.** Проверка `curl.exe -s -o NUL -w "%{http_code}" -I URL` → ожидаем `200`.

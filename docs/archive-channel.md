## 2. Схема наполнения (утверждена 03.11.2026)

**Файлы кладутся как есть**, без zip и без пересжатия: один файл — один пост
(`type=file`). Источники: `E:\наши изображения\мои` и `E:\наши изображения\камера`.

Порядок ленты — хронология 2006 → 2026:

```
**2006** — 3 папки · 81 файл · 196,2 МБ            заголовок года
**2006 · димкины** — 76 файлов · 110,1 МБ          заголовок папки
  [файл IMGP0374.JPG]  подпись «2006 · димкины»    по одному посту на файл
  ...
```

Правила:

- год папки: из имени → иначе медиана EXIF-дат фото → иначе даты файлов;
- внутри года папки идут по дате события (из имени, иначе по самой ранней
  фотографии);
- файлы в корне `мои` → группа «Разное» в своём году;
- `камера` → группа «камера» в своём году;
- служебный мусор (`Thumbs.db`, `*.db`, `*.cfg`, `*.info`) пропускается;
- в конце ленты — годовые каталоги (`**2014** — 17 папок …` + перечень папок),
  последним постом — «ОГЛАВЛЕНИЕ», он закрепляется через `PUT /chats/{id}/pin`.

План на 03.11.2026: **6 049 постов**, 5 873 файла, 45,2 ГБ (два видео больше
4 ГБ режутся на части, см. раздел 6).

## 3. Навигация: поиск, а не ссылки

В приватном канале MAX **не отдаёт ссылки на сообщения** (`url: null`; у
публичного канала AI — `https://max.ru/channel_ainow/AaGWfjLsAUw`). Поэтому
оглавление кликабельным быть не может.

Навигация держится на подписях: поиск в канале по «2014 ·» показывает все посты
года, по «2014 · 07.10.адлер» — конкретную папку. Заголовки папок и годов нужны
как якоря в ленте.

**Уведомления отключить нельзя**: для каналов `notify` всегда `true` (официальная
документация), поэтому 6 049 постов дадут столько же пушей. На время заливки
канал нужно заглушить в клиенте.

## 4. Поведение типов загрузки (замерено 02.11.2026)

| Тип | Что происходит | Замер |
| --- | --- | --- |
| `image` | пережимает и уменьшает картинку | 2304×3072 / 3 607 046 Б → 1440×1920 / **154 790 Б** |
| `video` | перекодирует видео | mp4 329 309 Б → 282 444 Б |
| `file` | сохраняет **байт-в-байт** | zip 196 Б и txt 64 Б вернулись с теми же sha256 |

Лимиты: `image` 50 МБ и ≤ 7680×7680; `video` 250 МБ; `audio` 256 МБ и ≤ 60 мин;
`file` **4 ГБ, 1 файл на сообщение**.

Проверено дополнительно:

- кириллица сохраняется и в имени файла в MAX, и в путях внутри zip
  (`Кабардинка 2007 (часть 1 из 2).zip` вернулся с тем же именем);
- у вложения `file` есть `filename`, `size`, `fileId` и прямая ссылка
  `https://fd.oneme.ru/getfile?...` (скачивается без авторизации, байты совпали);
- resumable-загрузка не работает: POST тела с `Content-Type:
  application/octet-stream` (с `Content-Range` и без) → `406 Not Acceptable`;
  рабочий путь — multipart целиком;
- текст поста без `"format": "markdown"` сохраняет `**` литерально — формат
  указывать обязательно;
- `notify: false` в канале отклоняется: `errors.send-message.channel-notify`;
- скорость заливки на 143,7 МБ: 64 с ≈ 2,25 МиБ/с и 575 с ≈ 0,25 МиБ/с
  (сеть/троттлинг). Ориентир: 45–62 ГБ — от 8 часов до нескольких суток.

## 5. Инструменты

| Файл | Назначение |
| --- | --- |
| `tools/archive_plan.py` | обход папок, определение годов, сборка плана постов в `local/archive-plan.json` + отчёт `local/archive-plan.txt` |
| `tools/archive_upload.py` | исполнение плана: загрузка, `POST /messages`, GET-контроль (имя и размер), журнал, докачка, повтор при `attachment.not.ready` |

Запуск:

```bash
python tools/archive_plan.py                 # пересобрать план
python tools/archive_upload.py --dry-run --year 2006
python tools/archive_upload.py --year 2006   # залить один год
python tools/archive_upload.py               # последний прогон: каталоги + закреп
```

Журнал `local/archive-journal.jsonl` — по строке на пост (`i`, `kind`, `mid`,
`path`, `verify`). Повторный запуск пропускает всё со `status: done`. Ошибки
пишутся как `failed` и остаются в очереди. Отчёт прогона —
`local/archive-run.txt`.

Режим `--year YYYY` берёт только этот год (заголовки, папки, файлы), а годовые
каталоги и закреп оставляет на финальный общий прогон — иначе каталог 2006
оказался бы в середине ленты.

## 6. Два видео больше 4 ГБ: решение — резать на части

Не влезают в лимит `file` (4 ГБ):

- `E:\наши изображения\мои\2 часть Воспоминания о школе  Выпускной 2024_HD.mp4` — 8,2 ГБ;
- `E:\наши изображения\мои\Выпускной 21 школа Сальск 2024\1 часть Воспоминания о школе  Выпускной 2024_HD.mp4` — 8,4 ГБ.

Решение владельца (03.11.2026): **резать на части по 1,9 ГБ**, байты сохраняются.
Загрузчик делает это сам (`kind: file_split`):

- части кэшируются в `local/split/<имя>.part01…` (манифест
  `local/split-manifest.json`), повторный запуск не режет заново;
- каждая часть — отдельный пост с подписью «ГГГГ · Папка · часть N из M»;
- после частей — пост с инструкцией склейки (`copy /b` для Windows,
  `cat` для Linux/macOS) и sha256 исходного файла;
- проверено на тестовом файле: 4 части, sha256 исходника = sha256 склейки.

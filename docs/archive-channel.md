## 2. Поведение типов загрузки (замерено 02.11.2026)

Главный вывод: **архивом в смысле «исходник без изменений» является только
`type=file`.**

| Тип | Что происходит | Замер |
| --- | --- | --- |
| `image` | пережимает и уменьшает картинку | фото 2304×3072, 3 607 046 Б → 1440×1920, **154 790 Б**; sha256 не совпал |
| `video` | перекодирует видео | mp4 329 309 Б (480×480, 4 с) → 282 444 Б; sha256 не совпал |
| `file` | сохраняет **байт-в-байт** | zip 196 Б и txt 64 Б вернулись с теми же sha256 |

Дополнительно проверено для `file`:

- принимает `.zip`, имя файла сохраняется (`zip-test.zip`);
- в `GET /messages/{mid}` есть `filename`, `size`, `fileId` и прямая ссылка
  `https://fd.oneme.ru/getfile?...` — файл скачивается без авторизации,
  скачанное совпало с оригиналом по sha256;
- ограничения: **1 файл на сообщение**, до **4 ГБ**; комбинировать можно только
  с `inline_keyboard`, не с картинками и не с видео.

Лимиты по типам (dev.max.ru/docs-api/methods/POST/uploads):

| `type` | форматы | лимит |
| --- | --- | --- |
| `image` | JPG, JPEG, PNG, GIF, TIFF, BMP, HEIC | 50 МБ **и** ≤ 7680×7680 |
| `video` | MP4, MOV, MKV, WEBM | 250 МБ |

## 3. Технические детали, проверенные в работе

- `POST /uploads?type=file` → `{url, token?}`; для `file` токен приходит **из
  ответа на загрузку** (`{"fileId":…, "token":…}`), в ответе `/uploads` его нет.
- Загрузка — `curl.exe -X POST -F "data=@<файл>" "<url>"` (multipart, без
  заголовка `Authorization`; так загружались и видео в `ainow`).
- **Resumable-режим не заработал**: POST тела с `Content-Type:
  application/octet-stream` (с `Content-Range` и без) отдаёт `406 Not
  Acceptable`. Рабочий путь — multipart целиком; при обрыве начинать заново
  с нового `POST /uploads`.
- Ответ загрузки видео — пустое тело или `<retval>1</retval>` (XML), не JSON.
- В канале **`notify` обязательно `true`** (или поле не передавать): с
  `notify: false` приходит `{"code":"proto.payload","message":"errors.send-message.channel-notify"}`.
- После загрузки файл обрабатывается: перед `POST /messages` пауза, при
  `attachment.not.ready` — повтор с растущим интервалом (токен переиспользуется).
- Скорость загрузки (замер на 143,7 МБ): 64 с ≈ **2,25 МиБ/с** в первом прогоне
  и 575 с ≈ **0,25 МиБ/с** во втором (похоже на троттлинг/сеть). Ориентир для
  56,75 ГиБ: от ~8 часов до ~2 суток непрерывной заливки.

## 5. Открытое решение владельца

Схема наполнения не выбрана. Варианты:

1. **Zip-тома по папкам-событиям** (рекомендация агента): ~250–300 сообщений,
   тома ≤ 2–3,8 ГБ, к каждому — `манифест.txt` с sha256 и инструкция сборки для
   разрезанных файлов. Плюсы: структура альбомов сохраняется, сообщений мало,
   байты целы. Минус: чтобы посмотреть — скачать том.
2. **Пофайлово как `file`**: 5 884 сообщения, каждое фото доступно отдельно по
   своему имени, повреждение одного файла ничего не тянет. Минус: лента огромная,
   превью у вложений типа `file` нет.
3. **Гибрид**: фото томами, отдельные «избранные» — пофайлово.

Отдельно и независимо от схемы: **MAX не должен быть единственной копией**
(нет версионирования и гарантий хранения). Правило 3-2-1: оригиналы на внешнем
диске + облако (Яндекс Диск / Облако Mail.ru) + MAX как третья, «карманная»
копия.

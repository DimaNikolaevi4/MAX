🧰 **Replit + GitHub: как выдать ИИ-агенту не кабинет, а цех**

В прошлом посте мы разобрали чат — это звонок, а ИИ-агент — сотрудник, которому нужен кабинет. Кабинет выдали: облако или репозиторий на GitHub плюс токен доступа.
Но кабинет — это где сотрудник сидит. А где он работает руками? Где запускает код, тестирует, деплоит?
Здесь появляется Replit.

**Replit — это не редактор. Это цех**
Replit — облачная среда разработки в браузере. Ничего не нужно ставить и настраивать. Открыл — и работаешь.
Внутри Replit живёт Agent — встроенный ИИ-агент. Он умеет:
— планировать работу и разбивать задачу на шаги,
— писать код и сразу запускать,
— ставить зависимости и настраивать окружение,
— тестировать, находить ошибки и исправлять их,
— деплоить готовое приложение.

Agent 4 работает параллельно над несколькими задачами: бэкенд, фронтенд, авторизация, база данных. И может работать автономно часами.

**Где здесь GitHub?**
Replit и GitHub — не конкуренты. Это две половины одного процесса.
Replit — где агент делает: пишет код, запускает, тестирует, деплоит.
GitHub — где агент помнит: каждое изменение, каждую версию, каждый откат.
Синхронизация в один клик. Импортируйте существующий репозиторий или подключите пустой. Agent автоматически создаёт Checkpoints — снимки состояния. Если что-то пошло не так — один клик, и вы откатываетесь.
GitHub даёт то же, но с полной историей коммитов. Агент видит: этот подход сработал, этот сломался, здесь откатился и попробовал иначе. Это и есть накопление опыта.

**Но одного инструмента мало. Нужна методика**
Дать агенту Replit и GitHub — как выдать сотруднику цех и архив. Без плана он будет метаться.
Вот последовательность, которую мы используем.

**Шаг 1. Цель.**
Одно предложение: что строим и зачем.

**Шаг 2. Задачи.**
Не «сделать сайт», а «настроить репозиторий», «собрать структуру страниц», «подключить форму», «настроить деплой».

**Шаг 3. Чек-лист в GitHub.**
Каждая задача — пункт в файле внутри репозитория. GitHub — единственное место, которое агент видит и читает при каждом запуске. Чек-лист — это карта, по которой агент идёт сам.

Формат простой:
— [ ] Настроить структуру проекта
— ( ✅ ) Подключить репозиторий к Replit
— [ ] Собрать главную страницу
— [ ] Подключить форму
( ✅ ) — выполнено, [ ] — ещё нет.

**Шаг 4. Промпт.**
Не «сделай сайт», а инструкция по работе с чек-листом:

Общаемся на русском. Работаем с репозиторием [https://github.com/blob/******/SITE_V2_CHECKLIST.md](https://github.com/blob/******/SITE_V2_CHECKLIST.md). Подключись к репозиторию. Проходи чек-лист сверху вниз. Пропускай выполненные пункты ( ✅ ). Выполняй по пунктам невыполненные сверху вниз. Вопросы и спорные решения выноси сюда с вариантами решений.
Всё. Дальше агент делает сам: читает чек-лист, видит невыполненный пункт, начинает работу. Каждый шаг фиксируется коммитом или чекпоинтом. Застрял — спрашивает, но с вариантами: «Jekyll или чистый HTML?»
Что это даёт
Вы перестаёте быть диспетчером. Чек-лист в GitHub — состояние проекта в одном файле. Агент читает его, как сотрудник читает список задач.
Replit даёт агенту руки, GitHub — память. Вместе — непрерывный рабочий процесс.

Попробуйте: цель → 5–7 задач → чек-лист в GitHub → репозиторий к Replit → промпт из шага 4.
